# Candy框架系统函数替代模式文档

## 1. 概述

系统函数替代模式是Candy框架的高级功能，通过禁用并替换PHP原生系统函数，实现对核心功能的统一管理和扩展。该模式允许框架对HTTP响应、Cookie、Session等关键功能进行更精细的控制和增强，同时提供更好的安全性和一致性。

## 2. 功能定位

系统函数替代模式的主要目标是：

- 统一管理核心系统函数的行为
- 增强安全性（如防止HTTP头注入、会话劫持等）
- 提供一致的API接口
- 便于功能扩展和定制
- 支持框架级别的功能控制

## 3. 实现机制

### 3.1 启动条件

系统函数替代模式在框架初始化阶段自动检测并启动，启动条件为：

1. 存在文件 `CANDYPATH/.reload`
2. `\Extend\Adapter` 类已定义

```php
// 系统函数替代模式启动代码（Autoload.php 112-115行）
// 开启系统函数替代模式
if(is_file(CANDYPATH . '.reload') && class_exists('\Extend\Adapter')){
    \Extend\Adapter::init();
}
```

### 3.2 初始化流程

`Adapter::init()` 方法执行以下步骤：

1. **检查函数禁用状态**：验证PHP原生系统函数是否已正确禁用
2. **加载自定义系统函数**：从 `Source/Func/reload.func.php` 加载用户自定义函数
3. **加载框架函数实现**：从 `Candy/Func/reload.func.php` 加载框架提供的函数实现
4. **初始化HTTP功能**：调用 `Http::init()` 完成HTTP相关功能的初始化

```php
// Adapter类初始化方法核心流程
public static function init(): void
{
    try {
        self::checkFunctionsDisabled();
        
        // 加载自定义系统函数
        requireCache(CANDYPATH . 'Source/Func/reload.func.php');
        
        // 加载框架提供的系统函数实现
        requireCache(CANDYPATH . 'Candy/Func/reload.func.php');
        
        Http::init();
    } catch (\Exception $e) {
        \Candy\Core\Debug::showMessage($e->getMessage(), 'Shutdown');
    }
}
```

## 4. 被替换的核心函数

系统函数替代模式主要替换以下PHP原生系统函数：

### 4.1 HTTP响应头相关函数

| 函数名 | 功能 | 替换目的 |
|-------|------|---------|
| `header()` | 发送HTTP头信息 | 增强安全性，防止头注入攻击 |
| `header_remove()` | 移除已发送的HTTP头 | 统一管理响应头 |
| `headers_sent()` | 检查HTTP头是否已发送 | 提供更细粒度的控制 |
| `http_response_code()` | 设置HTTP响应状态码 | 统一状态码管理 |

### 4.2 Cookie相关函数

| 函数名 | 功能 | 替换目的 |
|-------|------|---------|
| `setcookie()` | 设置Cookie | 增强安全性，支持更复杂的Cookie策略 |

### 4.3 Session相关函数

| 函数名 | 功能 | 替换目的 |
|-------|------|---------|
| `session_create_id()` | 创建会话ID | 提供更安全的会话ID生成机制 |
| `session_id()` | 获取/设置会话ID | 统一会话ID管理 |
| `session_name()` | 获取/设置会话名称 | 统一会话名称配置 |
| `session_save_path()` | 设置会话保存路径 | 统一会话存储配置 |
| `session_status()` | 获取会话状态 | 提供更详细的会话状态信息 |
| `session_start()` | 启动会话 | 增强会话安全，支持自定义会话处理 |
| `session_write_close()` | 写入并关闭会话 | 优化会话写入性能 |
| `session_regenerate_id()` | 重新生成会话ID | 增强会话安全性 |

### 4.4 执行时间控制

| 函数名 | 功能 | 替换目的 |
|-------|------|---------|
| `set_time_limit()` | 设置脚本执行时间限制 | 统一执行时间管理 |

## 5. 配置要求

### 5.1 PHP配置

使用系统函数替代模式前，必须在 `php.ini` 中禁用相关原生函数：

```ini
; 禁用需要被框架替换的函数
disable_functions = "header,header_remove,headers_sent,http_response_code,setcookie,session_create_id,session_id,session_name,session_save_path,session_status,session_start,session_write_close,session_regenerate_id,set_time_limit"
```

### 5.2 框架配置

1. **启用标志**：在框架根目录创建 `.reload` 文件以启用该模式
2. **权限设置**：确保框架有足够权限读取和写入相关配置文件

## 6. 使用方法

### 6.1 启用系统函数替代模式

```bash
# 在框架根目录创建 .reload 文件以启用系统函数替代模式
touch /path/to/candy/.reload
```

### 6.2 自定义函数扩展

框架允许用户通过编辑 `Source/Func/reload.func.php` 文件来自定义函数实现：

```php
// 自定义header函数实现示例
function header(string $string, bool $replace = true, int $response_code = 0): void {
    // 自定义实现逻辑
    // 例如：添加安全头、验证头信息等
    
    // 调用框架内部实现
    \Candy\Func\header($string, $replace, $response_code);
}
```

### 6.3 禁用系统函数替代模式

```bash
# 删除 .reload 文件以禁用系统函数替代模式
rm /path/to/candy/.reload
```

## 7. 设计优势

系统函数替代模式的设计具有以下优势：

### 7.1 增强安全性

- 统一验证和过滤输入参数
- 防止常见的安全漏洞（如HTTP头注入、会话劫持等）
- 提供一致的安全策略

### 7.2 提高可维护性

- 集中管理核心功能实现
- 便于统一升级和修改
- 减少代码重复

### 7.3 增强扩展性

- 支持用户自定义函数实现
- 便于添加新功能和特性
- 提供一致的扩展接口

### 7.4 跨环境一致性

- 确保在不同环境下的行为一致性
- 减少环境差异导致的问题

## 8. 注意事项

1. **配置依赖性**：系统函数替代模式依赖正确的PHP配置和框架文件结构
2. **性能影响**：函数替换会带来轻微的性能开销，但通常可以忽略
3. **兼容性问题**：自定义函数实现需确保与PHP原生函数接口兼容
4. **调试复杂性**：问题排查时需要考虑自定义函数的影响
5. **版本更新**：框架升级时需注意函数实现的变化

## 9. 应用场景

系统函数替代模式适用于以下场景：

- 需要严格控制HTTP响应和请求处理的应用
- 对安全性要求较高的系统（如支付系统、管理后台等）
- 需要统一管理Session和Cookie的应用
- 需要定制核心系统函数行为的场景

## 10. 总结

系统函数替代模式是Candy框架的高级功能，通过禁用并替换PHP原生系统函数，实现了对核心功能的统一管理和增强。该模式提供了更好的安全性、一致性和扩展性，适用于对核心功能有严格控制要求的应用场景。

使用系统函数替代模式需要注意正确的配置和兼容性问题，但带来的安全性和可维护性提升通常是值得的。框架开发者和高级用户可以利用这一模式定制和扩展框架的核心功能，以满足特定的业务需求。
