# 多数据库切换功能使用说明

## 功能概述

框架支持在运行时按**配置别名**切换到不同的数据库连接。

**设计目的：库隔离**（多租户 / 多业务库 / 多应用数据空间）。  
每个别名对应一套独立数据空间；同一别名下可再配置 **write / read** 读写分库（主从），与隔离正交、互不冲突。

实现上使用 **CRC32** 为连接池生成键，相同配置复用连接，不同配置独立实例，避免用 `C()` 覆盖全局配置造成污染。

## 主要改进

### 1. 使用 CRC32 替代 MD5
- **性能提升**: CRC32 比 MD5 快得多，适合用作连接池的键值生成
- **避免配置污染**: 每个数据库连接实例独立存储配置，不再使用 `C()` 函数覆盖全局配置

### 2. 连接池优化
- 基于 CRC32 生成唯一连接池键值
- 相同配置只会创建一个连接实例
- 不同配置自动创建新的连接实例

### 3. 配置管理
- 新增 `currentConfig` 属性存储当前连接配置
- 新增静态 `configPool` 属性存储所有配置映射
- 提供 `getCurrentConfig()` 和 `getConfigPool()` 方法

## 配置方法

### 方法一：在配置文件中定义多个数据库（库隔离）

编辑配置文件 `Source/Inc/Config.inc.php`：

```php
<?php
return [
    'CHARSET'     => 'utf8mb4',
    'DRIVER'      => 'pdomysql',
    'DB'          => [
        // 默认库（主业务）
        'default' => [
            'HOST'     => 'localhost',
            'USER'     => 'root',
            'PASS'     => 'password123',
            'DBNAME'   => 'app_main',
            'TABPREFIX' => 'sa_',
        ],
        // 租户 / 子业务库（库隔离示例）
        'tenant_a' => [
            'HOST'     => 'localhost',
            'USER'     => 'tenant_a',
            'PASS'     => 'tenant_a_pass',
            'DBNAME'   => 'app_tenant_a',
            'TABPREFIX' => 'ta_',
            'CHARSET'  => 'utf8mb4',
        ],
        // 另一业务域独立库（如日志、商城）
        'shop' => [
            'HOST'     => 'localhost',
            'USER'     => 'shop',
            'PASS'     => 'shop_pass',
            'DBNAME'   => 'app_shop',
            'TABPREFIX' => 'sp_',
            'CHARSET'  => 'utf8mb4',
        ],
    ],
    // ... 其他配置
];
```

> 配置键名即隔离别名。扁平配置（含 `HOST`）读写同节点；需要主从时在**同一别名**下配置 `write` / `read`。

### 读写分库（主从，与隔离正交）

```php
'DB' => [
  'default' => [
      'write' => [
          'HOST' => '10.0.0.1',
          'USER' => 'app',
          'PASS' => '...',
          'DBNAME' => 'app_main',
          'TABPREFIX' => 'sa_',
      ],
      'read' => [
          [
              'HOST' => '10.0.0.2',
              'USER' => 'app_ro',
              'PASS' => '...',
              'DBNAME' => 'app_main',
              'TABPREFIX' => 'sa_',
          ],
      ],
  ],
  'tenant_a' => [
      'HOST' => 'localhost',  // 扁平：该租户库无分库，读写同连接
      'USER' => 'tenant_a',
      'PASS' => '...',
      'DBNAME' => 'app_tenant_a',
      'TABPREFIX' => 'ta_',
  ],
],
```

| 配置形态 | 行为 |
|---------|------|
| 含 `HOST` | 旧写法，读写同一连接 |
| 含 `write` / `read`（或 `master` / `slave`） | 按角色拆连接；无从库时读回退 write |
| 仅 `write` 无 `read` | 读也走 write |

**自动路由**（`D()` / `M()` 未强制角色时）：

| 操作 | 默认节点 |
|------|---------|
| `select` / `find` / `total` | `read` |
| `insert` / `update` / `delete` / 其他写操作 | `write` |
| 事务开启后 | 全程 `write` |

**强制角色**：

```php
D('User');                          // 自动路由
D('User', 'default', 'read');       // 强制读库
D('User', 'default@write');         // 紧凑写法
M('User', 'tenant_a')->useRead();   // 链式
```

### 方法二：在代码中直接使用配置数组

```php
// 使用配置数组（临时指向另一隔离库）
D('User', [
    'HOST'     => '192.168.1.200',
    'USER'     => 'custom_user',
    'PASS'     => 'custom_pass',
    'DBNAME'   => 'custom_db',
    'TABPREFIX' => 'cust_',
    'CHARSET'  => 'utf8mb4',
]);
```

## 使用示例

### 1. D() 函数 - 数据库表操作

#### 使用默认数据库
```php
// 使用默认配置操作 User 表
$userDb = D('User');
$userDb->select();
```

#### 使用配置别名（库隔离）
```php
// 访问租户 A 隔离库
$users = D('User', 'tenant_a')->select();

// 访问商城业务库
$orders = D('Order', 'shop')->select();
```

#### 按当前租户 ID 自动索库（第二参数 true）
```php
// 须已实现 getTenantID，且 DB/DBLIST 中有对应别名（或 getTenantDbConfig）
$orders = D('Order', true)->select();
$orders = D('Order', true, 'read')->select();
```

#### 使用配置数组
```php
// 直接使用配置数组
$users = D('User', [
    'HOST'     => '192.168.1.200',
    'USER'     => 'root',
    'PASS'     => '123456',
    'DBNAME'   => 'test_db'
])->select();
```

#### 跨项目调用并使用不同隔离库
```php
// 调用 Admin 项目的 User 表，落在 tenant_a 库
$adminUsers = D('Admin://User', 'tenant_a')->select();
```

### 2. M() 函数 - 模型操作

#### 使用默认数据库
```php
// 使用默认配置的 User 模型
$userModel = M('User');
$userModel->select();
```

#### 使用配置别名
```php
// 租户隔离库中的 User 模型
$users = M('User', 'tenant_a')->select();

// 商城库
$orders = M('Order', 'shop')->select();
```

#### 按当前租户 ID 自动索库（第二参数 true）
```php
// 须已实现 getTenantID，且 DB/DBLIST 中有对应别名（或 getTenantDbConfig）
$orders = M('Order', true)->select();
$orders = M('Order', true, 'read')->select();
```

#### 使用配置数组
```php
// 使用自定义配置
$userModel = M('User', [
    'HOST'     => '192.168.1.200',
    'USER'     => 'root',
    'PASS'     => '123456',
    'DBNAME'   => 'test_db'
]);
```

#### 跨项目并使用不同隔离库
```php
// Admin 项目的 User 模型，使用 tenant_a 库
$adminUserModel = M('Admin://User', 'tenant_a');
```

### 3. 高级用法

#### 同时操作多个隔离库
```php
// 主业务库
$mainUsers = D('User')->select();

// 租户库
$tenantUsers = D('User', 'tenant_a')->select();

// 商城库
$orders = D('Order', 'shop')->select();
```

#### 在模型中按隔离库读写
```php
class UserModel
{
    public function copyFromTenant(string $alias)
    {
        // 从指定隔离库读取
        $rows = M('User', $alias)->select();

        // 写入默认库
        foreach ($rows as $user) {
            M('User')->add($user);
        }
    }
}
```

#### 获取当前连接配置
```php
$db = D('User', 'tenant_a');
$currentConfig = $db->getCurrentConfig();
print_r($currentConfig);
```

#### 获取所有配置池
```php
$configPool = \Candy\Extend\DB\DBServer::getConfigPool();
print_r($configPool);
```

## 连接池机制

### 键值生成规则

1. **默认配置**: 使用 `'default'` 作为键名
2. **配置别名**: 使用隔离别名本身作为键名（如 `'tenant_a'`, `'shop'`）
3. **配置数组**: 使用 `CRC32` 生成键名（如 `'db_1234567890'`）

```php
// 相同隔离库共享连接
$db1 = D('User', 'tenant_a');   // tenant_a 连接
$db2 = D('Order', 'tenant_a');  // 复用 tenant_a 连接

// 不同隔离库独立连接
$db3 = D('User', [/* config A */]);  // 创建连接 A
$db4 = D('User', [/* config B */]);  // 创建连接 B
```

### 连接池管理

框架使用两层连接池：

1. **配置池** (`DBServer::$configPool`): 存储配置映射
2. **连接池** (`Pdo::$links` / 各驱动 `$links`): 存储 PDO 连接实例

```php
// 清空配置池（用于测试或重置）
\Candy\Extend\DB\DBServer::clearConfigPool();
```

## 性能优化

### CRC32 vs MD5 对比

| 算法  | 速度（相对） | 输出长度     | 适用场景       |
|-------|-------------|-------------|---------------|
| MD5   | 1x          | 32 字符十六进制 | 加密、签名     |
| CRC32 | 5-10x       | 10 位整数    | 连接池键值、缓存 |

使用 CRC32 的优势：
- 更快的键值生成速度
- 整数键值，内存占用更小
- 足够避免连接池键值冲突

## 注意事项

### 1. 配置验证
系统会自动验证数据库配置的完整性，缺少必要参数时会提示错误：
- `HOST`: 数据库主机地址
- `USER`: 数据库用户名
- `PASS`: 数据库密码
- `DBNAME`: 数据库名称

### 2. 配置别名注册
使用隔离别名前，确保别名已在全局配置或配置池中注册：

```php
// 方式1：在配置文件中注册
'DB' => [
    'tenant_a' => [ /* ... */ ]
]

// 方式2：通过 G() 函数注册（运行时）
G('DBLIST', [
    'tenant_a' => [ /* ... */ ]
]);
```

### 3. 对象唯一性
框架会根据以下因素生成唯一的数据库/模型对象：
- 表名/模型名
- 应用名称
- 配置信息（隔离别名或 CRC32 键值）

相同参数会自动复用对象，不同参数会创建新实例。

### 4. 事务处理
**库隔离下各库事务独立**，不能跨库共享同一事务：

```php
$db1 = D('User');                 // default
$db2 = D('Order', 'shop');        // shop 隔离库

$db1->startTrans();  // 只影响 default
$db2->startTrans();  // 只影响 shop（独立事务）
```

## 技术实现细节

### 修改的文件

1. **Candy/Class/DB/DBServer.class.php**
   - `$currentConfig` / `$configPool`
   - `setLink()` 使用 CRC32 生成键值
   - `getCurrentConfig()`, `getConfigPool()`, `clearConfigPool()`

2. **Candy/Func/di.func.php**（`D()` / `M()`）
   - 按隔离别名生成唯一容器键，支持多库切换

### 向后兼容性

- 不传参数：使用默认配置
- 字符串参数：使用隔离别名
- 数组参数：使用配置数组（不污染全局 `C()`）

## 常见问题

### Q1: 配置别名不生效？
**A**: 确保别名已在 `Config.inc.php` 的 `DB` 或 `G('DBLIST')` 中注册。

### Q2: 如何查看当前使用的数据库配置？
**A**: 使用 `$db->getCurrentConfig()`。

### Q3: 多个相同配置会创建多个连接吗？
**A**: 不会，相同隔离配置会自动复用连接。

### Q4: 多库与读写分库是什么关系？
**A**: **正交**。`DB` 第一维是**库隔离**（选哪套数据）；同一别名下第二维是 **write/read**（选主从）。不要把 `slave` 做成顶层隔离别名。

### Q5: CRC32 会冲突吗？
**A**: 概率极低；关键隔离库请用配置别名，避免仅用匿名配置数组。

## 总结

- **目的**：库隔离 + 可选读写分库（主从）
- **手段**：`DB` 多别名 + `D()`/`M()` 第二参数选隔离库，第三参数或 `@read` / `useRead()` 强制角色
- **实现**：CRC32 连接池键、独立配置、不污染全局

请按隔离场景配置别名，不要误用为隐式读写分离。
