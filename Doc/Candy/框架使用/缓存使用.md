# Candy框架 缓存使用文档

## 1. 缓存功能概述

Candy框架提供了一套强大而灵活的缓存系统，支持多种缓存驱动和丰富的缓存操作API。该缓存系统采用抽象工厂模式设计，通过统一的接口操作不同类型的缓存驱动，实现了缓存操作的标准化和可扩展性。

### 1.1 核心特性

- **多种缓存驱动支持**：Memory、Apcu、Redis、Memcached、File等
- **自动驱动选择**：根据环境自动选择最适合的缓存驱动
- **分布式锁机制**：确保高并发环境下的数据一致性
- **多维数组缓存**：支持嵌套键值对操作（如`user.info.name`）
- **丰富的API**：提供完整的缓存操作方法，包括基础CRUD、数组操作、计数器等
- **连接池管理**：优化资源使用，提高性能
- **内置异常处理**：确保系统稳定性

### 1.1.1 关键语义（2026-07-18）

| 项 | 行为 |
|----|------|
| `get` 未命中 | 用哨兵区分合法 `null`/`false`；**负缓存仅进程内**，禁止写远端 STRING（避免污染 List） |
| `lPush`/`rPush` | `$cover` **默认 false**（追加并可建队）；`true` 表示先清空再写入 |
| 事务 | `get`/`has`/`ttl`/`mGet`/`mHas` **禁止**在事务中调用 |
| 熔断 | half-open：恢复窗口后仅一条探测，成功关闭 / 失败重开 |
| 热点续期 | `autoRenewSampleRate`（默认 10）采样续期，降低写放大 |
| List 元素（Redis） | 与 KV 一致走 `Binary::pack`，`lPop` 兼容历史裸字符串 |

冒烟：`php candy test:run cache_semantics_smoke`

### 1.2 缓存工作原理

Candy框架的缓存系统采用分层设计：

1. **接口层**：通过`Cache`抽象类定义标准接口
2. **实现层**：具体缓存驱动实现抽象接口
3. **工厂层**：通过`getCache()`函数创建缓存实例
4. **应用层**：应用程序通过统一接口使用缓存功能

## 2. 缓存初始化

### 2.1 使用`getCache()`函数创建缓存实例

`getCache()`是获取缓存实例的主要入口函数，位于`/Candy/Func/global.func.php`第1429行。该函数采用单例模式设计，确保全局只有一个缓存实例。

```php
// 创建或获取缓存实例
$cache = getCache();

// 检查缓存实例是否创建成功
if ($cache === false) {
    echo "缓存初始化失败";
}
```

### 2.2 缓存配置

缓存配置位于项目配置文件中，可通过`Config`配置项进行设置：

```php
$config = [
    'CACHE' => [
        'driver' => 'Redis', // 缓存驱动，可选值：auto, Memory, Apcu, Redis, Memcached, File, Gd
        'options' => [
            'host' => '127.0.0.1', // 缓存服务器地址
            'port' => 6379, // 缓存服务器端口
            'password' => '', // 缓存服务器密码
            'database' => 0, // 缓存数据库
            // 其他驱动特定配置...
        ]
    ]
];
```

### 2.3 自动驱动选择机制

当`driver`设置为`auto`时，框架会根据当前环境自动选择最合适的缓存驱动：

1. **Web服务器环境**：优先选择`Memory`驱动
2. **命令行环境(CLI)**：
   - 如果安装了`apcu`扩展，选择`Apcu`驱动
   - 否则选择`File`驱动

### 2.4 手动选择驱动

可以通过配置明确指定使用的缓存驱动：

```php
// 使用Redis驱动
$config['CACHE']['driver'] = 'Redis';

// 使用Memcached驱动
$config['CACHE']['driver'] = 'Memcached';

// 使用自定义驱动（需要实现Cache接口）
$config['CACHE']['driver'] = 'MyCustomCache';
```

## 3. 缓存驱动类型

Candy框架支持多种缓存驱动，每种驱动适用于不同的场景：

### 3.1 Memory驱动

- **特点**：基于内存的缓存，速度最快
- **适用场景**：临时数据缓存、单次请求内的数据共享
- **限制**：数据仅在当前请求有效，请求结束后自动清除

### 3.2 Apcu驱动

- **特点**：PHP的APC扩展提供的用户缓存
- **适用场景**：高并发Web应用、频繁访问的数据
- **依赖**：需要安装`apcu`扩展

### 3.3 Redis驱动

- **特点**：高性能的分布式缓存，支持丰富的数据结构
- **适用场景**：分布式系统、需要持久化的缓存数据
- **配置**：需要指定host、port等连接信息

### 3.4 Memcached驱动

- **特点**：内存分布式缓存系统
- **适用场景**：大规模分布式应用、需要高可用的缓存
- **配置**：需要指定host、port等连接信息

### 3.5 File驱动

- **特点**：基于文件系统的缓存
- **适用场景**：开发环境、小规模应用
- **限制**：性能相对较低，不适合高并发场景

### 3.6 GlobalData驱动

- **特点**：基于Workerman的全局数据共享解决方案
- **适用场景**：需要在多个进程间共享数据的应用
- **依赖**：需要启动GlobalData服务器

## 4. 缓存操作API

### 4.1 基础操作

#### 设置缓存

```php
// 设置简单缓存
$cache->set('key', 'value', 3600); // 缓存1小时

// 设置多维数组缓存
$cache->set('user.info', ['name' => '张三', 'age' => 25]);
$cache->set('user.info.name', '李四'); // 更新嵌套值

// 仅当键不存在时设置缓存
$cache->add('unique_key', 'value');
```

#### 获取缓存

```php
// 获取简单缓存
$value = $cache->get('key');

// 获取缓存并设置默认值
$value = $cache->get('non_existent_key', 'default_value');

// 获取多维数组缓存
$userInfo = $cache->get('user.info');
$userName = $cache->get('user.info.name');
```

#### 删除缓存

```php
// 删除简单缓存
$cache->delete('key');

// 删除多维数组缓存的特定字段
$cache->delete('user.info.age');
```

#### 检查缓存是否存在

```php
if ($cache->has('key')) {
    // 缓存存在
}
```

### 4.2 数组操作

#### 数组头部操作

```php
// 向数组头部添加元素
$cache->lPush('list', 'item1');
$cache->lPush('list', 'item2', 'item3');

// 移除并返回数组头部元素
$item = $cache->lpop('list');
```

#### 数组尾部操作

```php
// 向数组尾部添加元素
$cache->rpush('list', 'item1');
$cache->rpush('list', 'item2', 'item3');

// 移除并返回数组尾部元素
$item = $cache->rpop('list');
```

#### 获取数组范围元素

```php
// 获取数组所有元素
$list = $cache->lrange('list', 0, 0);

// 获取数组指定范围元素（分页）
$page1 = $cache->lrange('list', 0, 10); // 获取前10个元素
$page2 = $cache->lrange('list', 10, 10); // 获取第11-20个元素

// 排序获取元素
$sortedList = $cache->lrange('user_list', 0, 0, 'age', 'desc'); // 按年龄降序排序
```

### 4.3 计数器操作

```php
// 初始化计数器
$cache->set('counter', 0);

// 计数器自增
$cache->incr('counter');

// 计数器自减
$cache->decr('counter');
```

### 4.4 高级操作

#### 获取缓存剩余有效期

```php
// 获取缓存剩余有效期（秒）
$ttl = $cache->ttl('key');
// 返回值：
// -1: 缓存不存在或已过期
// 0: 永不过期
// >0: 剩余有效期（秒）
```

#### 清空所有缓存

```php
// 清空当前缓存驱动的所有缓存
$cache->clear();
```

## 5. 全局缓存与配置函数

Candy框架提供了四个核心全局函数，用于配置管理和缓存操作。这些函数位于`/Candy/Func/global.func.php`文件中，提供了便捷、高效的配置和缓存访问方式。

### 5.1 C函数：配置管理函数

C函数用于获取和设置配置参数，支持批量定义和多维数组操作。该函数在文件第269行定义，使用静态内存缓存提高性能。

**功能特点**：
- 支持简单配置获取和设置
- 支持多维数组配置操作（如`DB.HOST`）
- 支持批量配置设置
- 使用静态内存缓存，提高访问速度

**使用示例**：

```php
// 获取配置
$dbHost = C('DB_HOST'); // 获取DB_HOST配置值
$dbHost = C('DB.HOST'); // 获取DB数组中的HOST值

// 设置配置
C('DB_HOST', 'localhost'); // 设置DB_HOST配置值
C('DB.HOST', 'localhost'); // 设置DB数组中的HOST值

// 批量设置配置
C(['DB_HOST' => 'localhost', 'DB_PORT' => 3306]);

// 获取所有配置
$allConfig = C();
```

### 5.2 F函数：文件缓存函数

F函数用于文件缓存操作，支持设置、获取和删除文件缓存。该函数在文件第987行定义，使用静态内存缓存提高性能。

**功能特点**：
- 基于文件系统的持久化缓存
- 支持设置缓存有效期
- 使用静态内存缓存，减少文件I/O操作
- 支持缓存删除操作

**使用示例**：

```php
// 设置文件缓存
F('user_info', ['name' => '张三', 'age' => 25], 3600); // 缓存1小时

// 获取文件缓存
$userInfo = F('user_info');

// 删除文件缓存
F('user_info', null);
```

### 5.3 G函数：全局数据函数

G函数用于全局数据缓存，支持通过缓存驱动存储和获取全局数据。该函数在文件第1275行定义，可与各种缓存驱动配合使用。

**功能特点**：
- 支持多种缓存驱动（通过`getCache()`获取）
- 支持多维数组数据操作
- 支持批量数据设置
- 当无缓存驱动时，自动降级使用C函数进行内存缓存

**使用示例**：

```php
// 设置全局数据
G('site.title', 'Candy框架官网');
G('user.info', ['name' => '张三', 'age' => 25]);

// 获取全局数据
$siteTitle = G('site.title');
$userInfo = G('user.info');

// 批量设置全局数据
G(['site.title' => 'Candy框架官网', 'site.version' => '1.0.0']);

// 获取所有全局数据
$allData = G();
```

### 5.4 T函数：原子数据函数

T函数用于原子数据缓存，支持在请求生命周期内保持数据一致性。该函数在文件第4290行定义，使用UUID标识确保数据隔离。

**功能特点**：
- 基于UUID的请求级数据隔离
- 支持多维数组数据操作
- 支持批量数据设置
- 在非Web环境下自动降级使用C函数

**使用示例**：

```php
// 设置原子数据
T('request.user_id', 123);
T('request.path', '/index/index');

// 获取原子数据
$userId = T('request.user_id');
$path = T('request.path');

// 批量设置原子数据
T(['request.user_id' => 123, 'request.path' => '/index/index']);

// 获取所有原子数据
$allAtomicData = T();
```

## 6. 分布式锁机制

Candy框架的缓存系统内置了分布式锁机制，用于解决高并发环境下的缓存一致性问题。锁机制在以下操作中自动启用：

- `set()`：设置缓存时
- `delete()`：删除缓存时
- 数组操作：如`lPush()`、`rpush()`、`lpop()`、`rpop()`等
- 计数器操作：`incr()`、`decr()`等

分布式锁通过`handleMultiDimensionalArray()`方法获取，在操作完成后自动释放，确保在高并发环境下的数据一致性和完整性。

## 7. 缓存最佳实践

### 7.1 缓存键命名规范

- **使用有意义的键名**：如`user:123:info`而不是`u123i`
- **添加前缀**：区分不同模块的缓存，如`blog:post:123`
- **避免特殊字符**：特别是在使用文件缓存驱动时

### 7.2 缓存策略

- **选择合适的缓存驱动**：根据应用场景选择性能和功能匹配的驱动
- **合理设置缓存有效期**：避免缓存过期策略不当导致的问题
- **使用多级缓存**：结合本地缓存和分布式缓存提高性能
- **定期清理过期缓存**：避免缓存膨胀

### 7.3 性能优化

- **批量操作**：尽量使用批量API减少网络请求
- **避免频繁更新**：对频繁变化的数据谨慎使用缓存
- **使用缓存预热**：系统启动时加载常用数据到缓存
- **监控缓存命中率**：及时调整缓存策略

## 8. 常见问题与解决方案

### 8.1 缓存初始化失败

**问题**：`getCache()`返回`false`

**解决方案**：
- 检查缓存驱动配置是否正确
- 确保缓存服务器正常运行（如Redis、Memcached）
- 检查缓存扩展是否安装（如Apcu）
- 查看系统日志获取详细错误信息

### 8.2 缓存数据不一致

**问题**：高并发环境下缓存数据出现不一致

**解决方案**：
- 利用框架内置的分布式锁机制
- 避免长时间持有锁
- 合理设计缓存键结构

### 8.3 缓存性能问题

**问题**：缓存操作响应缓慢

**解决方案**：
- 检查缓存服务器性能
- 优化网络连接
- 使用更高效的缓存驱动
- 减少不必要的缓存操作

## 9. 扩展与定制

### 9.1 自定义缓存驱动

可以通过实现`Cache`抽象类创建自定义缓存驱动：

```php
namespace APP\Extend;

use Candy\Core\Cache;

class MyCustomCache extends Cache {
    // 实现抽象方法
    protected function __rawSet(string $key, mixed $value = '', int $ttl = 0): mixed {
        // 自定义实现
    }
    
    protected function __rawGet(string $key, mixed $default = null): mixed {
        // 自定义实现
    }
    
    // 实现其他抽象方法...
}
```

### 9.2 注册自定义驱动

在配置文件中注册自定义缓存驱动：

```php
$config['CACHE']['driver'] = 'MyCustomCache';
```

Candy框架的缓存系统提供了一套完整、高效、灵活的缓存解决方案，支持多种缓存驱动和丰富的API。通过统一的接口设计，实现了缓存操作的标准化和可扩展性，满足了不同应用场景的缓存需求。

合理使用缓存系统可以显著提高应用程序的性能和响应速度，减少数据库压力，提升用户体验。建议开发者根据实际应用场景选择合适的缓存驱动和缓存策略，充分发挥缓存系统的优势。
