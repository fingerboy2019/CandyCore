# Candy框架单项目与多项目开发方式

## 1. 概述

Candy框架支持两种开发模式：单项目模式（默认）和多项目模式（ALLINONE模式）。通过简单的配置，可以在同一个框架实例下运行多个独立的项目，实现资源共享和统一管理。

## 2. 单项目模式

### 2.1 概述

单项目模式是Candy框架的默认开发模式，适用于只需要开发一个独立应用的场景。在这种模式下，项目文件直接位于框架根目录结构中。

### 2.2 实现原理

```php
// Autoload.php 第71行
$Applies = dirname(str_replace("\\", DS, __DIR__)) . DS;
```

当未定义`ALLINONE`常量时，框架会自动将项目根目录设置为框架所在的上级目录，即整个框架目录结构就是一个项目。

### 2.3 目录结构

```
candy/                 # 框架根目录
├── Application/       # 应用目录
│   ├── Controllers/   # 控制器
│   ├── Models/        # 模型
│   ├── Views/         # 视图
│   └── ...            # 其他应用目录
├── Config/            # 配置目录
├── Public/            # 静态资源目录
├── Runtime/           # 运行时目录
├── Candy/             # 框架核心目录
└── index.php          # 入口文件
```

### 2.4 使用方式

1. 直接使用框架默认配置即可
2. 在框架根目录下的`index.php`中初始化框架
3. 所有业务逻辑直接在`Application`目录下开发

## 3. 多项目模式（ALLINONE模式）

### 3.1 概述

多项目模式允许在同一个框架实例下运行多个独立的项目，每个项目可以有自己的配置、控制器、模型和视图。这种模式适用于需要开发多个相关或不相关应用的场景，可以有效共享框架资源和减少维护成本。

### 3.2 实现原理

```php
// Autoload.php 第54-69行
if(defined('ALLINONE')){
    $appDir = CANDYPATH . 'Applies';

    //优先根据域名判断项目
    if(isset($_SERVER['HTTP_HOST'])){
        $domain = $_SERVER['HTTP_HOST'];
        $Applies = $appDir . DS . $domain . DS;    //根据域名判断项目目录
    }else{
        $Applies = $appDir . DS . 'default'. DS;    //默认项目目录
    }

    //判断项目是否存在
    if(!is_dir($appDir)){
        //不存在报错404
        T('S404', 'File Not Found.'); 
    }
}
```

当定义了`ALLINONE`常量时，框架会：
1. 创建或使用`CANDYPATH . 'Applies'`作为所有项目的根目录
2. 根据HTTP_HOST（域名）自动判断当前应该加载哪个项目
3. 如果没有HTTP_HOST（如CLI环境），则使用默认项目（default）
4. 如果项目目录不存在，返回404错误

### 3.3 配置方法

要启用多项目模式，需要在入口文件中定义`ALLINONE`常量：

```php
// public/index.php
define('ALLINONE', true);

// 引入框架初始化文件
require_once __DIR__ . '/../Candy/Autoload.php';
```

### 3.4 目录结构

```
candy/                         # 框架根目录
├── Applies/                   # 多项目根目录
│   ├── project1.example.com/  # 项目1（按域名命名）
│   │   ├── Application/       # 项目1的应用目录
│   │   ├── Config/            # 项目1的配置目录
│   │   ├── Public/            # 项目1的静态资源目录
│   │   └── Runtime/           # 项目1的运行时目录
│   ├── project2.example.com/  # 项目2（按域名命名）
│   │   ├── Application/       # 项目2的应用目录
│   │   ├── Config/            # 项目2的配置目录
│   │   ├── Public/            # 项目2的静态资源目录
│   │   └── Runtime/           # 项目2的运行时目录
│   └── default/               # 默认项目（CLI环境使用）
├── Candy/                     # 框架核心目录（共享）
└── public/                    # 公共入口目录
    └── index.php              # 入口文件
```

### 3.5 域名配置

要让多项目模式正常工作，需要配置Web服务器将不同的域名指向同一个框架入口文件。以Nginx为例：

```nginx
server {
    listen 80;
    server_name project1.example.com project2.example.com;
    root /path/to/candy/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass 127.0.0.1:9000;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        include fastcgi_params;
    }
}
```

## 4. 两种模式的比较

| 特性 | 单项目模式 | 多项目模式 |
|------|------------|------------|
| 适用场景 | 单个独立应用 | 多个相关或不相关应用 |
| 配置复杂度 | 低（默认） | 中（需要定义常量和配置域名） |
| 资源共享 | 不适用（只有一个项目） | 高（共享框架核心代码） |
| 项目隔离 | 不适用 | 高（每个项目有独立的配置和目录） |
| 维护成本 | 低（单个项目） | 中（多个项目需要分别维护） |

## 5. 切换与迁移

### 5.1 从单项目模式切换到多项目模式

1. 定义`ALLINONE`常量
2. 创建`Applies`目录
3. 将原项目文件复制到`Applies/{domain}/`目录下
4. 配置域名指向

### 5.2 从多项目模式切换到单项目模式

1. 移除`ALLINONE`常量定义
2. 将项目文件从`Applies/{domain}/`目录复制到框架根目录
3. 恢复默认目录结构

## 6. 最佳实践

### 6.1 单项目模式
- 适合小型应用或独立项目
- 开发和部署简单，无需额外配置
- 可以快速启动项目开发

### 6.2 多项目模式
- 适合需要开发多个应用的团队或公司
- 可以有效共享框架资源和减少维护成本
- 便于统一管理和升级框架版本
- 建议为每个项目创建独立的Git仓库进行版本控制

## 7. 注意事项

1. **域名配置**：在多项目模式下，确保Web服务器正确配置了域名指向
2. **目录权限**：确保`Applies`目录和各项目目录有正确的读写权限
3. **配置隔离**：每个项目的配置文件是独立的，修改一个项目的配置不会影响其他项目
4. **静态资源**：每个项目的静态资源应该放在各自项目目录下的`Public`目录中
5. **运行时目录**：框架会为每个项目创建独立的运行时目录，确保有足够的磁盘空间

通过Candy框架的单项目和多项目开发模式，可以灵活适应不同规模和需求的项目开发，提高开发效率和资源利用率。
