# Candy 框架项目构建与初始化

## 概述

Build 类是 Candy 框架的核心组件之一，负责自动化创建项目结构、应用程序、扩展插件等系统组件。它提供了完整的目录创建、文件生成和项目初始化功能，大大简化了项目的搭建过程。

## 核心功能

### 1. 项目结构自动化创建

Build 类可以根据配置自动创建完整的项目目录结构，包括：

- 应用程序目录结构
- 公共资源目录
- 模板目录
- 运行时缓存目录
- 配置文件目录

### 2. 基础文件生成

自动生成项目所需的核心文件：

- 控制器基类
- 路由配置文件
- 视图模板文件
- 配置文件
- 语言包文件

### 3. 多类型应用支持

支持创建多种类型的应用：

- 主应用程序 (Main Application)
- 扩展插件 (Addon)
- 功能插件 (Plugin)

### 4. 单项目与多项目模式

支持两种开发模式：

- 单项目模式：默认模式，框架目录结构直接作为单个项目
- 多项目模式 (ALLINONE)：多个独立项目共享同一个框架实例

## Build 类核心方法

### start() - 项目初始化入口

```php
public static function start(): void
```

该方法是框架初始化的核心入口，负责创建整个项目的目录结构、配置文件和基础类文件。

**执行流程：**
1. 检查初始化锁文件，避免重复初始化
2. 处理 Markdown 相关功能
3. 创建运行时目录
4. 根据请求参数创建不同类型的应用
5. 生成各种配置文件和基础类文件
6. 记录初始化日志

**触发方式：**
- URL 参数：`?start`
- 命令行参数：`--start`
- 框架首次运行时自动调用

### runtime() - 创建运行时目录

```php
private static function runtime(): void
```

创建框架运行所必需的临时文件和缓存目录：

- 系统缓存目录
- 模板组合文件目录
- 控制器缓存目录
- 模型缓存目录
- 日志目录

### mkdir() - 创建目录结构

```php
private static function mkdir(array $dirs): void
```

批量创建目录并设置适当的访问权限 (0755)。

### touch() - 创建或写入文件

```php
public static function touch(string $fileName, string $str): void
```

创建文件并写入内容，如果文件已存在则跳过操作。自动创建文件所在的目录结构，并设置适当的文件权限 (0644)。

### bulidSpaces() - 创建应用空间

```php
public static function bulidSpaces($name, $type = ''): bool
```

创建不同类型的应用空间：

- **主应用**：空字符串作为类型参数
- **扩展插件**：`addon` 作为类型参数
- **功能插件**：`plug` 作为类型参数

│   ├── Class/           # 通用类库

│   ├── Func/            # 函数库

## 新项目、控制器、扩展和插件创建

### 1. 新项目控制器创建

#### 1.1 通过URL参数创建

```
http://your-domain.com/?start
```

或使用命令行：
```bash
php build.php project Admin
```

#### 1.2 通过代码创建

```php
// 创建名为 "Admin" 的应用
Build::bulidSpaces('Admin');
```

#### 1.3 自动生成的控制器结构

创建成功后，会在 `Application/Admin/` 目录下生成以下控制器相关文件：

```
Application/Admin/
├── Controller/
│   ├── Common.class.php   # 控制器基类
│   └── Index.class.php    # 默认首页控制器
├── Model/                 # 模型目录
├── Views/                 # 视图目录
├── Languages/             # 语言包目录
└── ...
```

#### 1.4 控制器文件内容

**Common.class.php（控制器基类）：**
```php
namespace App\Controller\Admin;

define('CANDY') OR die('You Are A Bad Guy. o_O???');

class Common extends Action {
    function init(){
    }
}
```

**Index.class.php（默认控制器）：**
```php
namespace App\Controller\Admin;

define('CANDY') OR die('You Are A Bad Guy. o_O???');

class Index extends Action {
    function index(){
        //hook demo.php
        $this->display();
    }
}
```

### 2. 扩展插件创建

#### 2.1 通过URL参数创建

```
http://your-domain.com/?add=addon&name=DemoAddon
```

- `add=addon` 表示创建扩展插件
- `name` 参数指定插件名称

#### 2.2 通过代码创建

```php
// 创建名为 "DemoAddon" 的扩展插件
Build::bulidSpaces('DemoAddon', 'addon');
```

#### 2.3 自动生成的扩展结构

创建成功后，会在 `Addons/DemoAddon/` 目录下生成扩展插件结构：

```
Addons/DemoAddon/
├── Controller/             # 扩展控制器目录
│   ├── Common.class.php # 扩展控制器基类
│   └── Index.class.php  # 扩展默认控制器
├── Model/               # 扩展模型目录
├── Views/                # 扩展视图目录
└── ...
```

#### 2.4 扩展特性

- 扩展插件使用独立的命名空间 `App\Addon\DemoAddon`
- 可以通过URL直接访问扩展功能
- 支持与主应用交互和数据共享

### 3. 功能插件创建

#### 3.1 通过URL参数创建

```
http://your-domain.com/?add=plug&name=DemoPlug
```

- `add=plug` 表示创建功能插件
- `name` 参数指定插件名称

#### 3.2 通过代码创建

```php
// 创建名为 "DemoPlug" 的功能插件
Build::bulidSpaces('DemoPlug', 'plug');
```

#### 3.3 自动生成的插件结构

创建成功后，会在 `Plugins/DemoPlug/` 目录下生成功能插件结构：

```
Plugins/DemoPlug/
├── Controller/          # 插件控制器目录
├── Model/            # 插件模型目录
├── Views/             # 插件视图目录
├── Hook/              # 插件钩子目录
└── conf.php           # 插件配置文件
```

#### 3.4 插件特性

- 功能插件专注于提供特定功能模块
- 通过钩子机制与主应用集成
- 支持灵活的配置和扩展

## 配置选项

### 1. 单项目与多项目切换

在 `index.php` 文件中定义 `ALLINONE` 常量来启用多项目模式：

```php
// 启用多项目模式
define('ALLINONE', true);
```

### 2. 项目初始化状态

可以通过配置 `APP_INIT_STATUS` 来控制项目的初始化状态：

```php
// 已完成初始化
C(['APP_INIT_STATUS' => true]);

// 未完成初始化
C(['APP_INIT_STATUS' => null]);
```

### 3. 模板相关配置

```php
// 模板风格
C(['TPLSTYLE' => 'default']);

// 模板路径
C(['APP_TPL_PATH' => 'Home@./Template']);
```

## 最佳实践

### 1. 优先使用自动化构建

推荐使用 Build 类的自动化构建功能来创建项目，避免手动创建目录结构可能导致的错误。

### 2. 初始化后检查目录结构

项目初始化完成后，建议检查生成的目录结构和文件，确保所有必要的组件都已创建。

### 3. 定期清理运行时目录

运行时目录会积累缓存文件和日志，建议定期清理以释放磁盘空间。

### 4. 多项目模式下的域名配置

在多项目模式下，确保域名解析正确配置，以便框架能够正确识别不同的项目。

## 常见问题

### 1. 初始化失败

**问题**：访问 `?start` 后没有生成项目结构

**解决方案**：
- 检查服务器文件权限
- 确保 `Runtime` 目录可写
- 查看错误日志获取详细信息

### 2. 重复初始化

**问题**：多次访问 `?start` 会重复创建文件

**解决方案**：
- Build 类会自动创建初始化锁文件 `Runtime/init.lock`
- 初始化完成后，再次访问不会重复创建

### 3. 多项目模式下项目识别错误

**问题**：域名对应的项目没有正确识别

**解决方案**：
- 确保域名解析正确
- 检查 `APPINIT` 常量是否正确定义
- 查看 `CANDYPATH/Applies/` 目录结构

## 总结

Build 类为 Candy 框架提供了强大的自动化项目构建功能，通过简单的操作即可快速创建完整的项目结构和基础文件。它支持单项目和多项目模式，能够满足不同规模和类型的项目需求。合理利用 Build 类可以大大提高开发效率，减少手动配置的错误。
