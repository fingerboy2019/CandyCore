# Candy框架类库使用指南

## 1. 概述

本文档详细介绍Candy框架的类库编写规范和第三方类库引入方式。Candy框架采用了灵活的自动加载机制，支持多种类库组织方式，同时兼容第三方类库的集成。

> **注意**：本文档不包含以`Candy`命名空间开头的框架核心类库。

## 2. 自动加载机制

Candy框架的自动加载由`Candy\Core\Autoload`类实现，采用了基于命名空间的自动加载策略，同时兼容Composer自动加载。

### 2.1 核心特性
- 支持多种命名空间格式的类文件自动加载
- 实现了缓存机制以减少IO操作，提升性能
- 兼容Composer自动加载
- 支持项目内置扩展、框架内置扩展和外置扩展的加载

### 2.2 加载顺序

当请求一个类时，自动加载器会按照以下顺序搜索类文件：

1. **项目内置扩展类**：`APP_PATH/Vendor/`
2. **框架内置扩展类**：`CANDYPATH/Candy/Vendor/`
3. **框架内全局类**：`CANDYPATH/Candy/Class/Vendor/`
4. **框架外置扩展类**：`CANDYROOT/Source/Vendor/`
5. **Composer类库**：通过`CANDYPATH/Vendor/autoload.php`加载

## 3. 类库编写规范

### 3.1 命名规范

#### 3.1.1 类名规范
- 类名采用大驼峰命名法（PascalCase）
- 类名应清晰表达其功能
- 避免使用缩写，除非是广为人知的缩写

#### 3.1.2 文件名规范
- 类文件命名与类名保持一致
- 标准类文件后缀为`.class.php`
- 简单工具类文件后缀可为`.php`

#### 3.1.3 目录结构
- 类库应按照功能或类型组织到相应的目录中
- 支持多级目录结构，目录名采用小写字母
- 复杂类库应创建独立的目录，如`Apidoc/`、`Workerman/`等

### 3.2 代码风格

#### 3.2.1 命名空间
- 第三方类库应使用自己的命名空间，避免与框架核心命名空间冲突
- 命名空间应与目录结构保持一致
- 命名空间使用反斜杠(`\`)分隔

#### 3.2.2 类定义
- 类定义应包含必要的注释文档
- 类成员变量应明确访问修饰符（public、protected、private）
- 方法定义应包含参数类型声明和返回值类型声明

#### 3.2.3 注释规范
- 类和方法应使用PHPDoc风格注释
- 注释应包含功能描述、参数说明、返回值说明等
- 重要的代码片段应添加单行注释

### 3.3 文件结构

一个标准的类文件结构如下：

```php

/**
 * 类库名称
 * 
 * 类库功能描述
 * 
 * @author 作者名
 * @date 2025-12-15
 */

// 命名空间定义
namespace VendorName\LibraryName;

// 类定义
class LibraryClass {
    /**
     * 成员变量说明
     * 
     * @var string
     */
    protected $property;
    
    /**
     * 方法说明
     * 
     * @param string $param 参数说明
     * @return bool 返回值说明
     */
    public function method(string $param): bool {
        // 方法实现
        return true;
    }
}
```

## 4. 第三方类库引入方式

Candy框架支持多种第三方类库的引入方式，包括：

### 4.1 直接放置方式

将第三方类库直接放置在以下目录之一：

1. **项目内置扩展**：`APP_PATH/Vendor/`
   - 适用于项目特定的类库
   - 加载优先级最高

2. **框架内置扩展**：`CANDYPATH/Candy/Vendor/`
   - 适用于框架默认提供的第三方类库
   - 如Apidoc、Console、Workerman等

3. **框架外置扩展**：`CANDYROOT/Source/Vendor/`
   - 适用于用户自定义的全局扩展

### 4.2 命名空间映射

对于使用命名空间的第三方类库，可以通过以下方式引入：

1. **标准命名空间映射**：
   - 命名空间与目录结构保持一致
   - 如`VendorName\LibraryName`对应`VendorName/LibraryName.php`

2. **特殊路径配置**：
   - 通过`specialClass`配置实现特殊路径映射
   - 配置文件位于`/www/wwwroot/Candy/Candy/Config/Specialclass.php`

### 4.3 Composer方式

Candy框架兼容Composer自动加载，可以通过Composer引入第三方类库：

1. 在项目根目录创建`composer.json`文件
2. 运行`composer install`安装类库
3. 类库将自动加载，无需额外配置

## 5. 类库使用示例

### 5.1 直接使用第三方类库

#### 5.1.1 简单类库

假设我们有一个简单的工具类`MyUtil`：

**文件路径**：`APP_PATH/Vendor/MyUtil.class.php`

```php

/**
 * 我的工具类
 * 
 * 提供一些常用的工具方法
 */

class MyUtil {
    /**
     * 格式化日期
     * 
     * @param int $timestamp 时间戳
     * @return string 格式化后的日期字符串
     */
    public static function formatDate(int $timestamp): string {
        return date('Y-m-d H:i:s', $timestamp);
    }
}
```

**使用方式**：

```php
// 直接使用，自动加载器会自动加载类文件
echo MyUtil::formatDate(time());
```

#### 5.1.2 带命名空间的类库

**文件路径**：`APP_PATH/Vendor/MyCompany/MyLibrary.class.php`

```php
<?php
/**
 * MyCompany库
 * 
 * 提供企业级功能
 */

namespace MyCompany;

class MyLibrary {
    /**
     * 获取企业信息
     * 
     * @return array 企业信息
     */
    public function getCompanyInfo(): array {
        return [
            'name' => 'My Company',
            'address' => 'China'
        ];
    }
}
```

**使用方式**：

```php
// 使用命名空间
use MyCompany\MyLibrary;

$library = new MyLibrary();
print_r($library->getCompanyInfo());
```

### 5.2 集成第三方框架类库

以`Workerman`为例，它是一个高性能的PHP Socket服务器框架：

**文件路径**：`CANDYPATH/Candy/Vendor/Workerman/Worker.php`

**使用方式**：

```php
// 使用Workerman命名空间
use Workerman\Worker;

// 创建一个Worker监听2345端口，使用http协议
$http_worker = new Worker("http://0.0.0.0:2345");

// 启动4个进程对外提供服务
$http_worker->count = 4;

// 当收到客户端发来的数据后返回hello world给客户端
$http_worker->onMessage = function($connection, $data) {
    // 向客户端发送hello world
    $connection->send('hello world');
};

// 运行worker
Worker::runAll();
```

### 5.3 使用Composer类库

假设我们通过Composer安装了`monolog/monolog`日志库：

```bash
composer require monolog/monolog
```

**使用方式**：

```php
// 使用Monolog命名空间
use Monolog\Logger;
use Monolog\Handler\StreamHandler;

// 创建日志记录器
$log = new Logger('name');
$log->pushHandler(new StreamHandler('/path/to/your.log', Logger::WARNING));

// 添加日志记录
$log->warning('Foo');
$log->error('Bar');
```

## 6. 性能优化

### 6.1 缓存机制

Candy框架的自动加载器实现了缓存机制，可以将类文件的路径信息缓存起来，减少IO操作：

- 缓存键名为`class.` + 类名的MD5值
- 缓存内容包含类名、类型和文件路径
- 开发环境（DEV模式）下会禁用缓存

### 6.2 类库组织建议

- 将常用的类库放置在项目内置扩展目录（`APP_PATH/Vendor/`）
- 对于大型类库，建议使用Composer引入
- 避免在一个文件中定义过多的类
- 合理使用命名空间，避免类名冲突

## 7. 常见问题

### 7.1 类文件找不到

**解决方法**：
1. 检查类名和文件名是否一致
2. 检查命名空间与目录结构是否一致
3. 检查类文件是否放置在正确的目录中
4. 清除缓存（调用`Autoload::clearCache()`）

### 7.2 类名冲突

**解决方法**：
1. 为类库添加命名空间
2. 使用`use`关键字为类设置别名
3. 调整类库的加载顺序

### 7.3 Composer类库不生效

**解决方法**：
1. 确认已安装Composer类库（`vendor/autoload.php`文件存在）
2. 检查`composer.json`配置是否正确
3. 运行`composer dump-autoload`重新生成自动加载文件

## 8. 总结

Candy框架提供了灵活且高效的类库加载机制，支持多种类库组织方式。通过遵循本文档的规范，您可以轻松地编写和集成第三方类库，提高开发效率和代码质量。

框架的自动加载机制不仅简化了类库的使用，还通过缓存机制提升了性能，是框架的重要组成部分。
