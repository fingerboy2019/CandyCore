# Candy框架插件系统使用文档

> 钩子体系总览（静态 Plugin 钩子 + 动态 `listen` 标签）见 **[Hook 钩子系统](Hook钩子系统.md)**。

## 1. 插件系统概述

Candy框架的插件系统是一个强大的扩展机制，允许开发者通过插件来扩展、修改或覆盖框架和项目的核心功能。插件系统主要由`App`类和`Hook`类共同实现，提供了以下核心功能：

- 类的扩展与覆盖
- 钩子机制与事件监听
- 插件配置与管理
- 支持同名项目插件的特殊处理

## 2. 插件目录结构

标准插件目录结构如下：

```
plugins/
├── 插件名称/
│   ├── conf.php          # 插件配置文件
│   ├── Hook/             # 钩子文件目录
│   │   ├── 钩子文件1.php
│   │   ├── 钩子文件2.html
│   │   └── ...
│   ├── Action/           # 控制器扩展目录
│   │   ├── Index.class.php
│   │   └── ...
│   ├── Model/            # 模型扩展目录
│   │   ├── User.class.php
│   │   └── ...
│   └── Common/           # 公共类扩展目录
│       └── Common.class.php
└── ...
```

## 3. 插件配置文件

每个插件都需要一个`conf.php`配置文件，用于定义插件的基本信息和行为：

```php
<?php
return [
    'name'      => '插件名称',
    'title'     => '插件标题',
    'description' => '插件描述',
    'version'   => '1.0.0',
    'author'    => '作者信息',
    'enable'    => 1,       // 插件是否启用（1=启用，0=禁用）
    'installed' => 1,       // 插件是否已安装（1=已安装，0=未安装）
    'rank'      => 100,     // 插件优先级，数字越小优先级越高
    'pertain'   => ''       // 插件所属项目
];
```

## 4. App类中的插件处理机制

### 4.1 类自动加载与扩展

`App`类的核心功能是处理类的自动加载和扩展，主要通过`getCmpiledFile`方法实现。当加载一个类时，系统会：

1. 检查是否存在原始类文件
2. 检查是否存在对应的扩展类文件
3. 根据情况决定如何处理类的继承关系

### 4.2 类扩展的三种模式

#### 4.2.1 模式一：直接扩展（带extends关键字）

当扩展类中包含`extends`关键字时，系统会保持原有继承关系：

```php
// 原始类 (Index.class.php)
class Index extends Common {
    // 原始代码
}

// 扩展类 (插件目录/Action/Index.class.php)
class Index extends Common {
    // 扩展代码
}
```

在这种模式下，扩展类会完全替换原始类。

#### 4.2.2 模式二：自动继承基础类（不带extends关键字）

当扩展类中不包含`extends`关键字时，系统会自动创建一个基础类（添加Base后缀），并让扩展类继承这个基础类：

```php
// 原始类 (Index.class.php)
class Index extends Common {
    // 原始代码
}

// 扩展类 (插件目录/Action/Index.class.php)
class Index {
    // 扩展代码
}
```

编译后的效果：

```php
// 自动创建的基础类
class IndexBase extends Common {
    // 原始代码
}

// 扩展类继承基础类
class Index extends IndexBase {
    // 扩展代码
}
```

#### 4.2.3 模式三：合并扩展（同时存在原始类和扩展类）

当同时存在原始类和扩展类时，系统会将原始类重命名为`$className . 'Base'`，然后让扩展类继承这个Base类：

```php
// 原始类 (User.class.php)
class User extends Model {
    public function getInfo() {
        return '原始方法';
    }
}

// 扩展类 (插件目录/Model/User.class.php)
class User {
    public function getInfo() {
        $info = parent::getInfo();
        return $info . ' - 扩展内容';
    }
}
```

编译后的效果：

```php
// 原始类重命名为Base类
class UserBase extends Model {
    public function getInfo() {
        return '原始方法';
    }
}

// 扩展类继承Base类
class User extends UserBase {
    public function getInfo() {
        $info = parent::getInfo();
        return $info . ' - 扩展内容';
    }
}
```

### 4.3 同名项目插件的特殊处理

当插件名称与项目名称相同时（`$k == T('RAPPNAME')`），系统会自动将其视为已安装和启用状态：

```php
// 在Hook类的getEnableHooks方法中
if((isset($hook['installed']) && $hook['installed'] == 1 && isset($hook['enable']) && $hook['enable'] == 1) || $k == T('RAPPNAME') || $k == $hook['pertain']){
    $enable_hooks[$k] = $hook;
}
```

这种机制允许项目内部也可以使用插件系统的扩展功能，实现代码的模块化和可维护性。

## 5. Hook类中的插件管理

### 5.1 钩子机制

钩子机制允许开发者在特定的代码位置插入自定义逻辑，主要通过以下方法实现：

- `add()`: 动态添加行为到标签
- `listen()`: 监听并触发标签事件
- `exec()`: 执行指定行为
- `import()`: 批量导入标签与行为配置

### 5.2 钩子文件处理

钩子文件是插件与框架交互的另一种方式，通过`processHook`方法处理：

```php
private static function processHook(string $hookfile): string
{
    // 获取所有启用的钩子
    $hooks = self::getEnableHooks();
    $s = '';
    
    foreach(array_keys($hooks) as $v){
        if(empty($hooks[$v])) continue;
        
        // 构建钩子文件路径
        $hook = C('PLUGPATH') . $v . '/Hook/' .$hookfile;
        
        // 千人千面特性支持
        $hook2 = '';
        if(C('HALLMARK') != null){
            if(substr($hook, -4) == '.php'){
                $hook2 = substr($hook, 0, -4) . '_' . C('HALLMARK') . '.php';
            }else{
                $hook2 = substr($hook, 0, -5) . '_' . C('HALLMARK') . '.html';
            }
        }
        $hook = is_file($hook2) ? $hook2 : $hook;
        
        // 读取并处理钩子文件内容
        if(is_file($hook)){
            $s2 = stripWhitespace(file_get_contents($hook));
            // 移除文件开头的exit语句和PHP标签
            $s2 = preg_replace('#^<\?php\s*exit;\?>\s{0,2}#i', '', $s2);
            if(substr($s2, 0, 5) == '<?php' && substr($s2, -2, 2) == '?>'){
                $s2 = substr($s2, 5, -2);
            }
            $s .= $s2;
        }
    }
    return $s;
}
```

### 5.3 插件的启用与禁用

插件的启用与禁用状态通过配置文件和数据库共同管理：

```php
// 在Hook类的getHooks方法中
$conf += [
    'enable' => $hook_list[$v]['enable'] ?? 0,
    'installed' => $hook_list[$v]['installed'] ?? 0,
    'plugid' => $hook_list[$v]['plugid'] ?? 0,
    'rank' => $hook_list[$v]['rank'] ?? 100,
    'pertain' => $hook_list[$v]['pertain'] ?? ''
];
```

## 6. 插件开发实例

### 6.1 创建一个简单的插件

1. 创建插件目录结构：

```
plugins/
└── MyPlugin/
    ├── conf.php
    ├── Action/
    │   └── Index.class.php
    └── Hook/
        └── header.html
```

2. 编写插件配置文件：

```php
// conf.php
return [
    'name' => 'MyPlugin',
    'title' => '我的插件',
    'description' => '这是一个示例插件',
    'version' => '1.0.0',
    'author' => 'Candy框架',
    'enable' => 1,
    'rank' => 100
];
```

3. 扩展控制器类：

```php
// Action/Index.class.php
class Index {
    public function index() {
        echo '这是插件扩展的index方法';
        // 调用父类方法
        parent::index();
    }
}
```

4. 创建钩子文件：

```html
<!-- Hook/header.html -->
<div class="plugin-header">
    <h2>这是插件添加的头部内容</h2>
</div>
```

### 6.2 在模板中使用钩子

```php
// 在模板文件中
// hook header.html
```

系统会自动替换`// hook header.html`为所有启用插件中`header.html`钩子文件的内容。

## 7. 高级功能

### 7.1 类的覆盖与扩展

通过插件系统，开发者可以：

- **覆盖**：完全替换原始类的实现
- **扩展**：在保留原始功能的基础上添加新功能
- **修改**：修改原始类的特定方法
- **集成**：将多个插件的功能集成到一个类中

### 7.2 优先级管理

插件的执行顺序由`rank`参数控制，数字越小优先级越高：

```php
// 配置插件优先级
'rank' => 50  // 优先级高于默认值100
```

### 7.3 千人千面特性

插件系统支持根据`HALLMARK`配置加载不同的钩子文件：

```php
// 当C('HALLMARK') = 'mobile'时
// 会优先加载header_mobile.html而不是header.html
```

## 8. 最佳实践

1. **保持插件的独立性**：每个插件应该专注于一个特定功能
2. **使用适当的扩展模式**：根据需求选择合适的类扩展模式
3. **合理设置优先级**：确保插件按预期顺序执行
4. **充分测试**：在不同环境下测试插件的兼容性
5. **文档化**：为插件提供清晰的使用说明

## 9. 常见问题

### 9.1 插件不生效

- 检查插件是否已启用（`enable` = 1）
- 检查插件目录结构是否正确
- 检查类名和文件名是否匹配
- 清除缓存后重试

### 9.2 类扩展冲突

- 确保扩展类名与原始类名完全一致
- 避免在多个插件中同时扩展同一个类
- 使用优先级控制扩展顺序

### 9.3 钩子文件不加载

- 检查钩子文件路径是否正确
- 确保钩子文件内容格式正确
- 检查插件是否已启用

## 10. 总结

Candy框架的插件系统提供了强大而灵活的扩展机制，允许开发者通过插件来扩展、修改或覆盖框架和项目的核心功能。通过合理使用插件系统，可以提高代码的模块化程度和可维护性，同时为框架和项目提供良好的扩展性。
