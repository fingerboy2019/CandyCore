# 服务器部署模式

框架支持三种服务器运行模式，可根据业务需求灵活切换与组合。

---

## 模式总览

| 模式 | 命令 | HTTP 引擎 | 适用场景 |
|------|------|:---------:|----------|
| PHP-FPM | Nginx/Apache 代理 | PHP-FPM 多进程 | 传统虚拟主机、低并发 |
| Workerman | `php candy worker` | Workerman 多进程 | 高并发 HTTP + 后台服务一体 |
| Swoole | `php candy swoole` | Swoole 协程 | 极高并发 IO 密集型 HTTP |

三种模式的**后台服务**（GlobalData / IM / 计划任务 / 消息投递）统一由一套命令管理，不依赖 HTTP 引擎。

---

## 混合部署（推荐）

### 后台服务 + Workerman HTTP

```bash
# 后台服务（GlobalData、IM、计划任务、消息投递）
php candy process start -d

# Workerman HTTP Web（端口根据 Server.inc.php 配置）
php candy worker start -d
```

### 后台服务 + Swoole HTTP（协程）

```bash
# 后台服务不变
php candy process start -d

# Swoole 协程 HTTP Web（端口根据 Server.inc.php 配置）
php candy swoole start -d
```

> **注意**：`worker` 和 `swoole` 使用同一份 `Server.inc.php` 配置，启动前确保端口未被占用。

---

## 后台服务（Process Worker）

后台服务与 HTTP 引擎解耦，独立启停：

```bash
# 启动
php candy process start -d

# 停止
php candy process stop

# 重启
php candy process restart -d

# 查看状态
php candy process status

# 平滑重载（代码更新后）
php candy process reload
```

进程列表（定义在 `Source/Inc/Process.inc.php`）：

| 进程名 | 端口 | 功能 |
|--------|:----:|------|
| globaldata | `127.0.0.1:2207` | 全局变量共享 |
| scheduler | — | 秒级计划任务 |
| im_channel | `127.0.0.1:2210` | IM 消息通道 |
| im | `0.0.0.0:8109` | IM WebSocket |
| im_event_delivery | — | IM 事件可靠投递 |
| comms_delivery | — | Comms Hub 消息重试 |

## Workerman HTTP 模式

```bash
# 启动
php candy worker start -d

# 调试模式（前台运行，看日志）
php candy worker start

# 停止
php candy worker stop

# 重载
php candy worker reload
```

HTTP 配置在 `Source/Inc/Server.inc.php` 的 `webserver` 段：

```php
'webserver' => [
    'server' => [
        [
            'list' => [
                [
                    'domain' => 'www.candy.com',
                    'root'   => C('CANDYROOT'),
                    'port'   => 8008,
                    'count'  => 4,
                    'gzip'   => 2,
                ],
                [
                    'domain' => 'portal.candy.com',
                    'root'   => C('CANDYROOT'),
                    'port'   => 8008,
                ],
            ],
        ],
    ],
],
```

## Swoole 协程 HTTP 模式

### 依赖

- PHP 8.4+
- Swoole 扩展（`pecl install swoole`）

### 启动

```bash
# 启动
php candy swoole start -d

# 停止
php candy swoole stop

# 重启
php candy swoole restart
```

### 与 Workerman 差异

| 特性 | Workerman | Swoole |
|------|:---------:|:------:|
| 并发模型 | 多进程 | 单进程多协程 |
| 协程支持 | 无 | `enable_coroutine => true` |
| IO 等待 | 阻塞进程 | 挂起协程，不阻塞 |
| 请求隔离 | 进程天然隔离 | 需协程上下文隔离 |
| 适用场景 | 通用 | 高 IO 并发 |

Swoole 模式下框架自动启用协程安全机制：

| 组件 | 协程安全策略 |
|------|-------------|
| `C()` | `Coroutine::getContext()` 隔离 |
| `T()` | `Coroutine::getContext()` 隔离 |
| `G()` | 跳过本地缓存，直连 Redis |
| `I()` | 从协程隔离的 Request 快照读取 |
| `request()` | 路由完成后快照，协程内唯一 |
| `Container` | Request/Response 绑定到协程上下文 |
| `Session` | 强制走缓存驱动（Redis），跳过原生 session |

## 切换 HTTP 引擎

HTTP 引擎切换不影响后台服务：

```bash
# 停止当前 HTTP
php candy worker stop
# 或
php candy swoole stop

# 启动另一个 HTTP（后台服务无需重启）
php candy swoole start -d
```

Nginx 反向代理配置只需修改 `proxy_pass` 端口即可切换后端。

---

## Nginx 反向代理参考

```nginx
upstream candy_backend {
    server 127.0.0.1:8008;
}

server {
    listen 80;
    server_name www.candy.com portal.candy.com;

    location / {
        proxy_pass http://candy_backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

        # WebSocket 支持
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```
