# 权限节点管理

## 1. 类库概述

### 1.1 类定义

```php
final class Node {}
```

### 1.2 核心功能

Node类是Candy框架的权限节点管理核心类，负责处理权限验证、菜单生成、节点缓存等功能。它支持应用(APP)和插件(Addon)的权限节点统一管理，基于注释驱动的方式生成权限和菜单节点，并提供了完整的权限验证和菜单生成机制。

### 1.3 主要特性

- **注释驱动的节点定义**：通过在方法注释中使用@Auth和@Menu等属性来定义权限和菜单节点
- **标准化节点路径**：使用app/control/action三段式的标准化节点路径
- **多级权限验证**：支持超级管理员、控制器级别、方法级别等多级权限验证
- **缓存优化机制**：在非调试模式下缓存节点信息，提高性能
- **APP和Addon统一管理**：支持应用和插件的权限节点统一管理
- **菜单动态生成**：基于权限和菜单注释动态生成菜单列表

> **Admin 说明**：后台侧栏不设独立「菜单管理」模块或数据库菜单表。入口由 `#[Annotation(..., menu: true)]` 与 `classGroup`/`classGroupOrder`/`classOrder` 声明，经 `Node::getMenuList()` 扫描；组内二级序优先读方法注解 `order`，否则回退 `classOrder`。具体用户可见哪些项，由角色/补充权限中的 `auth: true` 节点过滤。详见 `raw/doc/AuthConvention.md` §1.4、`raw/doc/MenuSecondaryOrderDesign.md`。

## 2. 节点标准化机制

### 2.1 节点格式

Candy框架使用标准化的三段式节点路径：`app/control/action`

- **app**：应用名称，对应Application目录下的子目录
- **control**：控制器名称，对应应用下的控制器类
- **action**：操作方法名称，对应控制器中的方法

### 2.2 节点标准化方法

#### 2.2.1 获取当前节点

```php
/**
 * 获取当前访问节点
 * 
 * 根据当前请求上下文，组合应用名称、控制器和操作方法，生成当前访问的完整节点路径
 * 节点格式为：app/control/action
 * 
 * @return string 当前访问的完整节点路径
 */
public static function current(): string
```

**使用示例**：
```php
// 获取当前访问节点
$currentNode = Node::current(); // 返回类似 "admin/user/list"
```

#### 2.2.2 标准化任意节点

```php
/**
 * 获取标准访问节点
 * 
 * 将输入的节点路径标准化，确保节点格式为完整的三段式路径：app/control/action
 * 支持处理三种情况：
 * 1. 空节点：返回当前访问节点
 * 2. 单段节点：自动补全为当前应用和控制器下的方法
 * 3. 两段节点：自动补全为当前应用下的控制器和方法
 * 4. 三段节点：直接处理并返回标准化格式
 * 
 * @param string|null $node 节点路径，可以是null、单段、两段或三段格式
 * @return string 标准化后的完整节点路径(app/control/action)
 */
public static function full(?string $node = null): string
```

**使用示例**：
```php
// 空节点：返回当前节点
$node1 = Node::full(); // 返回当前节点，如 "admin/user/list"

// 单段节点：补全当前应用和控制器
$node2 = Node::full("add"); // 假设当前应用是admin，控制器是user，返回 "admin/user/add"

// 两段节点：补全当前应用
$node3 = Node::full("user/add"); // 假设当前应用是admin，返回 "admin/user/add"

// 三段节点：直接标准化
$node4 = Node::full("admin/user/add"); // 返回 "admin/user/add"
```

#### 2.2.3 获取操作节点

```php
/**
 * 获取完整的操作名称
 * 
 * 该函数用于获取完整的操作名称，通过调用Node类的full方法实现，
 * 可用于获取当前操作或指定操作的完整路径。
 * 
 * @param string $name 操作名称，默认为空（获取当前操作）
 * @return string 返回完整的操作名称
 */
function getOperate(string $name = ''): string
```

**功能描述**：
getOperate函数是Node::full()方法的包装器，用于获取完整的操作节点路径。它提供了更简洁的调用方式，便于在模板和业务逻辑中使用。

**执行流程**：
1. 接收操作名称参数（默认为空）
2. 调用Node::full()方法获取标准化的节点路径
3. 返回完整的操作节点路径

**使用示例**：
```php
// 获取当前操作完整路径
getOperate(); // 返回当前操作的完整节点路径，如 "admin/user/list"

// 获取指定操作完整路径
getOperate('user/index'); // 假设当前应用是admin，返回 "admin/user/index"

// 获取完整操作路径
getOperate('admin/user/add'); // 返回 "admin/user/add"
```

## 3. 权限验证机制

### 3.1 权限验证流程

Candy框架的权限验证遵循以下流程：

1. **超级管理员检查**：如果用户是超级管理员(Admin角色)，直接通过权限验证
2. **控制器级别检查**：检查控制器是否有`closeAuth`或`__noAuth`方法，如果有则无需权限验证
3. **方法级别检查**：检查方法注释中是否包含`@Authtrue`标记，如果有则需要权限验证
4. **用户权限检查**：根据用户拥有的权限节点列表进行验证

#### 3.1.1 整控制器免 RBAC 标记（`__noAuth` / `closeAuth`）

控制器内声明空的 `__noAuth()`（推荐）或 `closeAuth()` 时：

- **运行时**：`Node::checkAuth()` 跳过权限列表比对；仅对当前操作解析一次 `actInfo`（供日志标题等），不再遍历全部 public 方法。
- **扫描时**：控制器仍纳入 classList；`getAnnotationInfo()` 解析 Title/Menu/Icon/Log，但 **Auth 恒为 false**（不进权限分配树）。
- **侧栏**：`menu: true` 入口对所有登录用户可见（`getMenuList` 仅过滤 `auth: true` 且用户无权限的节点）。

适用于 **整类** 均不需 RBAC 的控制器（如登录、个人中心、站内信）。混合业务控制器请仅对需要 RBAC 的方法写 `auth: true`，不要加 `__noAuth()`。

> Admin 应用约定见 `raw/doc/AuthConvention.md` §1.5。

### 3.2 权限验证方法

#### 3.2.1 强制验证访问权限

```php
/**
 * 强制验证访问权限
 * 
 * 验证指定节点的访问权限，支持多种权限检查机制：
 * 1. 超级管理员(Admin)角色直接通过权限验证
 * 2. 检查控制器是否有closeAuth或__noAuth方法(表示无需权限验证)
 * 3. 检查方法注释中是否包含@Authtrue标记(表示需要权限验证)
 * 4. 根据用户拥有的权限节点列表进行验证
 * 
 * @param string|null $node 要验证的节点路径，null表示当前节点
 * @param array $auths 用户权限节点数组，默认为空(将从session获取)
 * @return array 包含两个元素的数组：[是否需要权限检查, 是否通过权限验证]
 */
public static function checkAuth(null|string $node = null, array $auths = []): array
```

**执行流程**：
1. 超级管理员(Admin角色)直接通过权限验证
2. 解析节点路径，获取应用名、控制器和操作方法
3. 检查控制器是否存在`closeAuth`或`__noAuth`方法(存在则无需权限验证)
4. 检查方法注释中是否包含`@Authtrue`标记(存在则需要权限验证)
5. 根据用户拥有的权限节点列表进行最终验证

**使用示例**：
```php
// 验证当前节点权限
list($needCheck, $passed) = Node::checkAuth();
if ($needCheck && !$passed) {
    // 没有权限，执行相应操作
    redirect(url('admin/login/index'));
}

// 验证指定节点权限
$userAuths = session('userAuths');
list($needCheck, $passed) = Node::checkAuth('admin/user/add', $userAuths);
if ($needCheck && !$passed) {
    // 没有权限
}
```

#### 3.2.2 应用用户权限

```php
/**
 * 应用用户权限
 * 
 * 根据用户权限过滤系统节点，确保用户只能访问有权限的节点
 * 支持重置缓存，适用于用户权限变更后刷新权限
 * 超级管理员直接返回所有权限节点
 * 
 * @param array $auths 用户权限节点数组，默认为空(将从session获取)
 * @param bool $force 是否强制重置所有缓存，默认为false
 * @return array 用户实际拥有的有效权限节点数组
 */
public static function applyUserAuth(array $auths = [], bool $force = false): array
```

**执行流程**：
1. 当`$force`为true时，清除相关缓存：
   - G('nodeAuthList', null)
   - G('nodeMenuList', null)
   - G('nodeMethodList', null)
   - G('checkAuthList', null)
   - G('checkMenuList', null)
2. 获取用户权限(为空则从session获取)
3. 获取系统中所有有效的权限节点列表
4. 超级管理员直接返回所有节点权限
5. 过滤用户权限，只保留系统中存在的有效节点

**使用示例**：
```php
// 应用用户权限
$userAuths = ['admin/user/list', 'admin/user/add'];
$validAuths = Node::applyUserAuth($userAuths);

// 权限变更后强制刷新
$validAuths = Node::applyUserAuth($newAuths, true);
```


### 4.2 菜单节点获取方法

#### 4.2.1 获取指定应用菜单

```php
/**
 * 获取菜单节点列表
 * 
 * 获取指定应用的菜单节点列表，支持权限验证过滤
 * 从控制器和方法的注释中解析菜单信息，根据@Menu属性生成菜单
 * 在非调试模式下会缓存结果以提高性能
 * 
 * @param string|null $appName 应用名称，null表示当前应用
```

```php

public static function getAppMenuList(): array
```


#### 4.2.3 获取所有菜单节点

```php
 * 合并应用菜单节点和插件菜单节点，提供统一的菜单节点访问接口
 * 结果会被缓存以提高性能
 * 
 * @return array 所有菜单节点数组，包含应用和插件的菜单节点信息

```

**使用示例**：

## 6. 缓存管理

### 6.1 缓存机制

为了提高性能，Node类在非调试模式下会缓存以下信息：

- 节点方法数据
- 菜单节点列表
- 权限节点列表
- 扁平化权限节点列表
- 扁平化菜单节点列表

### 6.2 缓存操作方法

#### 6.2.1 获取节点方法数据缓存

```php
/**
 * 获取节点方法数据缓存
 * 
 * 优先从Memcache获取节点方法数据缓存，如果Memcache不可用，则从类静态变量获取
 * 此方法提供统一的缓存访问接口，确保在不同环境下都能正常工作
 * 
 * @return array 节点方法数据数组
 */
public static function getMethodsData(): array
```

#### 6.2.2 设置节点方法数据缓存

```php
/**
 * 设置节点方法数据缓存

 * 
 * @param array $data 要缓存的节点方法数据
 * @return void
 */
public static function setMethodsData($data): void
```

#### 6.2.3 保存节点权限信息

```php
/**

```

### 6.3 `useNodeCache()` 与 `clearNodeCache()`（统一失效）

| 方法 | 作用 |
|------|------|
| `Node::useNodeCache()` | `DEBUG=0` 时返回 `true`，启用注解/菜单/权限扫描缓存 |
| `Node::clearNodeCache()` | **唯一**失效入口，清空进程内、G()、Memcache、注解扫描缓存 |

**开发环境**（`DEBUG=1`）：`useNodeCache()` 为 `false`，改注解后刷新页面即可，无需手动清缓存。

**生产环境**（`DEBUG=0`）：修改 `@Auth` / `@Menu`、控制器注解 title、或菜单 CRUD 后，必须调用 `Node::clearNodeCache()` 或执行：

```bash
php candy deploy:post    # 部署钩子：Node 缓存 + Runtime/Cache
php candy clear -c       # 清 Runtime/Cache（内含 clearNodeCache）
php candy clear --node     # 仅清 Node 注解缓存
```

业务代码中请直接调用 `Node::clearNodeCache()`，不要重复封装 `cleanNodeCache()` 之类私有方法。

部署脚本可调用项目钩子 `candy_post_deploy()`（定义于 `Source/Func/global.func.php`），或执行 `backend/scripts/post-deploy.sh`。

## 7. 权限节点的实际应用

### 7.1 控制器中定义权限和菜单

```php

namespace APP\Control\Admin;

class UserAction
{
    /**
     * 用户列表
     * 
     * @Menu(title="用户列表", group="user", auth=true)
     * @Auth(true)
     */
    public function list()
    {
        // 方法实现
    }
    
    /**
     * 添加用户
     * 
     * @Menu(title="添加用户", group="user", auth=true)
     * @Auth(true)
     */
    public function add()
    {
        // 方法实现
    }
    
    /**
     * 编辑用户
     * 
     * @Menu(title="编辑用户", group="user", auth=true)
     * @Auth(true)
     */
    public function edit()
    {
        // 方法实现
    }
    
    /**
     * 删除用户
     * 
     * @Auth(true)
     */

    {
        // 方法实现（没有菜单，只能通过列表页面操作）
    }

     * 登录页面

```

### 7.2 在控制器中进行权限检查

```php

namespace APP\Control\Admin;

class UserAction
{
    /**
     * 构造方法，在每个方法执行前调用
     */
    public function __construct()
    {
        // 验证当前节点权限
        list($needCheck, $passed) = Node::checkAuth();
        if ($needCheck && !$passed) {
            // 没有权限，重定向到登录页面
            redirect(url('admin/user/login'));
        }
    }
    
    // 其他方法...
}
```

```php
}
```

## 8. 最佳实践

### 8.1 节点命名规范

- 使用三段式路径：`app/control/action`
- 应用名称使用小写字母
- 控制器名称使用首字母大写的驼峰式命名
- 操作方法名称使用首字母小写的驼峰式命名
- 保持节点名称简洁明了，反映实际功能

### 8.2 节点获取建议

- 优先使用`getOperate()`函数获取操作节点路径，它是`Node::full()`的简洁包装器
- 在模板和视图层使用`getOperate()`函数提高代码可读性
- 在业务逻辑中保持节点路径获取方式的一致性，避免混合使用多种获取方式

### 8.3 权限定义建议

- 为所有需要权限控制的方法添加`@Auth(true)`注释
- 为所有需要显示在菜单中的方法添加`@Menu`注释
- 合理使用菜单分组，便于用户导航
- 为超级管理员保留所有权限，无需单独配置

### 8.4 性能优化

- 在生产环境中启用缓存（关闭调试模式）
- 权限变更后及时调用`applyUserAuth`方法并设置`force=true`刷新缓存
- 避免在循环中频繁调用权限验证方法

### 8.5 安全考虑

- 始终使用标准化的节点路径进行权限验证
- 不要在前端代码中硬编码权限判断逻辑
- 定期审查权限节点，确保权限设置合理
- 对敏感操作增加额外的安全验证

## 9. 总结

Candy框架的Node类提供了一套完整的权限节点管理系统，通过注释驱动的方式实现了灵活的权限控制和菜单生成。它支持：

- 节点标准化：统一的三段式节点路径格式
- 多级权限验证：超级管理员、控制器级别、方法级别验证
- 动态菜单生成：基于注释自动生成菜单
- 缓存优化：提高性能的缓存机制
- 应用和插件统一管理：支持应用和插件的权限节点统一处理

通过合理使用Node类，可以构建出安全、灵活、高效的权限管理系统。
