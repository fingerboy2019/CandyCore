# Candy框架模板引擎使用文档

## 1. 概述

Candy框架内置了一个功能强大的模板引擎，用于将PHP数据与HTML模板分离，实现MVC架构的视图层。该模板引擎支持类似Smarty的标签语法，提供了丰富的模板功能，包括变量输出、条件判断、循环控制、模板继承、包含文件等。

## 2. 基本使用方法

### 2.1 模板变量分配

在控制器中，可以使用 `assign` 方法将变量分配到模板中：

```php
// 分配单个变量
$this->assign('name', 'Candy框架');

// 批量分配变量
$this->assign([
    'title' => '首页',
    'content' => '这是首页内容',
    'list' => ['item1', 'item2', 'item3']
]);
```

### 2.2 清除变量

使用 `assignClear` 方法清除指定的模板变量：

```php
// 清除单个变量
$this->assignClear('name');

// 清除多个变量
$this->assignClear(['name', 'content']);
```

使用 `assignClearAll` 方法清除所有已分配的模板变量：

```php
// 清除所有变量
$this->assignClearAll();
```

### 2.3 API数据变量管理

使用 `apidata` 方法设置API数据变量（用于API响应）：

```php
// 设置单个API数据变量
$this->apidata('code', 200);

// 设置数组API数据变量
$this->apidata('data', ['name' => 'Candy框架', 'version' => '1.0.0']);
```

使用 `apidataClear` 方法清除指定的API数据变量：

```php
// 清除单个API数据变量
$this->apidataClear('code');

// 清除多个API数据变量
$this->apidataClear(['code', 'data']);
```

使用 `apidataClearAll` 方法清除所有已设置的API数据变量：

```php
// 清除所有API数据变量
$this->apidataClearAll();
```

### 2.4 模板渲染

使用 `display` 方法渲染并输出模板：

```php
// 渲染默认模板（控制器/操作名）
$this->display();

// 渲染指定模板
$this->display('User/profile');
```

如果需要获取渲染后的模板内容而不直接输出，可以使用 `fetch` 方法：

```php
$content = $this->fetch('User/profile');
```

### 2.5 信息提示

使用 `halt` 方法显示错误信息并终止执行：

```php
// 显示错误信息
$this->halt('操作失败，请稍后重试');
```

## 3. 模板语法

### 3.1 变量输出

使用 `<{$变量名}>` 语法输出变量：

```html
<h1><{$title}></h1>
<p><{$content}></p>
```

### 3.2 变量修饰器

可以使用管道符号 `|` 为变量添加修饰器：

```html
<!-- 输出大写 -->
<{$name|upper}>

<!-- 输出小写 -->
<{$name|lower}>

<!-- 截取字符串 -->
<{$content|substr:0:100}>
```

### 3.3 条件判断

使用 `if`、`elseif`、`else` 和 `/if` 标签进行条件判断：

```html
<{if $score >= 90}>
    <div class="excellent">优秀</div>
<{elseif $score >= 80}>
    <div class="good">良好</div>
<{elseif $score >= 60}>
    <div class="pass">及格</div>
<{else}>
    <div class="fail">不及格</div>
<{/if}>
```

### 3.4 循环控制

#### 3.3.1 foreach循环

使用 `foreach`、`foreachelse` 和 `/foreach` 标签进行循环：

```html
<ul>
    <{foreach from=$list item=item}>
        <li><{$item}></li>
    <{foreachelse}>
        <li>没有数据</li>
    <{/foreach}>
</ul>
```

支持key-value形式：

```html
<ul>
    <{foreach from=$userList item=user key=id}>
        <li><{$id}>: <{$user.name}></li>
    <{/foreach}>
</ul>
```

也支持简化语法：

```html
<ul>
    <{foreach $list as $item}>
        <li><{$item}></li>
    <{/foreach}>
</ul>

<!-- 带key的简化语法 -->
<ul>
    <{foreach $userList as $id => $user}>
        <li><{$id}>: <{$user.name}></li>
    <{/foreach}>
</ul>
```

### 3.5 模板继承

使用 `extend` 标签实现模板继承：

**父模板 (layout.html)**：

```html
<html>
<head>
    <title><{$title}></title>
</head>
<body>
    <div class="header">头部内容</div>
    <div class="content">
        <!-- 内容区块 -->
        <{block name="content"}>
        <{/block}>
    </div>
    <div class="footer">底部内容</div>
</body>
</html>
```

**子模板 (index.html)**：

```html
<{extend name="layout"}>

<{block name="content"}>
    <h1>首页内容</h1>
    <p>这是首页的具体内容</p>
<{/block}>
```

### 3.6 包含文件

使用 `include` 标签包含其他模板文件：

```html
<{include file="Public/header"}>

<div class="main">
    <!-- 主内容 -->
</div>

<{include file="Public/footer"}>
```

支持传递参数：

```html
<{include file="Common/menu" active="home"}>
```

### 3.7 系统函数调用

使用 `:` 符号调用系统函数：

```html
<!-- 输出当前时间 -->
<{:date('Y-m-d H:i:s')}>

<!-- 输出URL -->
<{:url('User/profile', ['id' => 1])}>
```

### 3.8 防缓存区域

使用 `nocache` 和 `/nocache` 标签标记不缓存的区域：

```html
<{nocache}>
    <!-- 这部分内容不会被缓存 -->
    当前时间：<{:date('Y-m-d H:i:s')}>
<{/nocache}>
```

### 3.9 原始输出

使用 `|raw` 修饰器输出原始HTML内容（不进行HTML转义）：

```html
<!-- 输出原始HTML -->
<{$html_content|raw}>
```

### 3.10 字面量标签

使用 `literal` 和 `/literal` 标签标记不需要解析的内容：

```html
<{literal}>
    <!-- 这里的内容不会被模板引擎解析 -->
    <{$variable}> 会被原样输出
<{/literal}>
```

### 3.11 Token标签

使用Token标签生成安全令牌：

```html
<!-- 生成普通token -->
<{_token_}>

<!-- 生成加密token -->
<{__token__}>

<!-- 生成csrf token -->
<{_csrf_}>
```

### 3.12 常量定义与判断

使用 `define` 标签定义常量：

```html
<{define name="CONST_NAME" value="constant_value"}>
```

使用 `defined` 标签判断常量是否已定义：

```html
<{defined name="CONST_NAME"}>
    常量已定义
<{/defined}>
```

使用 `notdefine` 标签判断常量是否未定义：

```html
<{notdefine name="CONST_NAME"}>
    常量未定义
<{/notdefine}>
```

### 3.13 空值判断

使用 `empty` 标签判断变量是否为空：

```html
<{empty name="$list"}>
    列表为空
<{/empty}>
```

使用 `notempty` 标签判断变量是否不为空：

```html
<{notempty name="$list"}>
    列表不为空
<{/notempty}>
```

### 3.14 资源导入

使用 `import` 标签导入CSS、JS等静态资源：

```html
<!-- 导入CSS文件 -->
<{import type="css" file="style.main"}>

<!-- 导入JS文件 -->
<{import type="js" file="lib.jquery"}>

<!-- 导入图片 -->
<{import type="jpg" file="images.banner"}>
```

## 4. 模板配置

### 4.1 模板目录与路径初始化

Candy框架通过`initTplPath`函数实现模板路径的自动初始化和配置。该函数是模板系统的核心，负责确定模板文件的实际路径、编译目录和缓存目录。

#### 4.1.1 模板路径初始化机制

`initTplPath`函数的核心功能包括：

1. **自定义模板路径配置**
   - 通过`APP_TPL_PATH`配置支持自定义模板路径
   - 支持单项目和多项目的模板路径配置

   ```php
   // 单项目自定义模板路径
   C('APP_TPL_PATH', 'Home@Application/Home/MyViews');
   
   // 多项目自定义模板路径
   C('APP_TPL_PATH', [
       'Home@Application/Home/MyViews',
       'Admin@Application/Admin/CustomViews'
   ]);
   ```

2. **多风格模板支持**
   - 通过`TPLSTYLE`配置指定模板风格
   - 模板文件会根据风格在Views目录下查找对应的子目录

   ```php
   // 使用default风格模板
   C('TPLSTYLE', 'default');
   ```

3. **设备自适应模板**
   - 自动检测移动设备并切换到mobile目录
   - 优先查找设备对应的模板目录

4. **模板资源路径设置**
   - 自动设置模板的资源文件路径
   - 通过`C_RES`配置可以在模板中引用资源文件

5. **编译目录和缓存目录**
   - 自动设置模板编译目录（`COMPOLE_DIR`）
   - 自动设置模板缓存目录（`CACHE_DIR`）
   - 目录结构根据应用名称、模板风格和设备类型自动生成

#### 4.1.2 模板路径结构

默认模板路径结构：
```
Application/
└── Home/               # 应用名称
    └── Views/          # 视图目录
        └── default/    # 模板风格
            ├── mobile/ # 移动设备模板
            ├── pc/     # PC设备模板
            └── Resource/ # 模板资源文件
```

插件模板路径结构：
```
Addons/
└── PluginName/         # 插件名称
    └── Views/          # 插件视图目录
        ├── mobile/     # 移动设备模板
        ├── pc/         # PC设备模板
        └── Resource/   # 插件资源文件
```

### 4.2 缓存设置

设置模板缓存：

```php
// 开启模板缓存
C('TPL_CACHE_ON', true);

// 设置缓存生命周期（秒）
C('TPL_CACHE_TIME', 3600);
```

### 4.3 模板分隔符设置

设置模板标签的分隔符：

```php
// 设置左分隔符
C('TPL_L_DELIM', '<{');

// 设置右分隔符
C('TPL_R_DELIM', '}>');
```

## 5. 高级功能

### 5.1 变量修饰器扩展

可以通过创建修饰器文件来扩展变量修饰器功能。在 `Candy/Extend/Modifier/` 目录下创建PHP文件，例如 `upper.php`：

```php
/**
 * 将字符串转换为大写
 * @param string $value 要转换的值
 * @return string 转换后的结果
 */
function view_modifier_upper($value) {
    return strtoupper($value);
}
```

然后在模板中使用：

```html
<{$name|upper}>
```

### 5.2 模板钩子

模板引擎支持钩子功能，可以在模板渲染过程中插入自定义代码：

```php
// 注册模板钩子
Hook::add('view_filter', function($content) {
    // 对渲染后的内容进行处理
    return $content;
});
```

### 5.3 千人千面模板

模板引擎支持根据配置的标识加载不同的模板文件，实现千人千面的效果：

```php
// 设置模板标识
C('HALLMARK', 'user123');
```

此时会优先加载带有 `_user123` 后缀的模板文件。

### 5.4 模板编译

使用 `compileFile` 方法编译模板文件：

```php
// 编译指定模板文件
$this->compileFile('user/index.html');
```

## 6. 最佳实践

1. **模板与逻辑分离**：模板中应尽量避免复杂的PHP逻辑，只负责数据展示
2. **使用模板继承**：通过模板继承减少重复代码，提高可维护性
3. **合理使用缓存**：对不经常变化的页面开启模板缓存，提高性能
4. **安全输出**：默认情况下模板引擎会自动转义HTML内容，确保输出安全
5. **使用变量修饰器**：通过修饰器统一处理变量的格式化输出
6. **避免直接操作数据库**：模板中禁止执行数据库操作或复杂计算
7. **使用Token标签**：在表单中使用Token标签防止CSRF攻击
8. **合理组织模板文件**：按功能模块组织模板文件，提高代码的可维护性

## 7. 注意事项

1. 模板文件中禁止直接插入PHP代码（`<?php ?>`）
2. 避免在模板中进行数据库操作或复杂计算
3. 变量名不能使用系统保留名称：`foreach`、`view`、`define`、`const`、`request`、`server`、`get`、`post`、`cli`、`ismobile`
4. 确保模板目录和编译目录具有可写权限
5. 在开发环境中建议关闭模板缓存，方便调试
6. 使用`|raw`修饰器时要确保内容安全，避免XSS攻击
7. 避免在模板中使用过多的条件判断和循环，影响页面渲染性能
8. 导入资源时要注意文件路径和文件类型的正确性

## 8. 示例模板

```html
<{extend name="layout"}>

<{block name="content"}>
    <div class="container">
        <h1><{$title}></h1>
        
        <div class="search-form">
            <form action="<{:url('Search/index')}>" method="get">
                <input type="text" name="keyword" placeholder="搜索...">
                <button type="submit">搜索</button>
                <input type="hidden" name="_token_" value="<{_token_}>" />
            </form>
        </div>
        
        <div class="article-list">
            <{notempty name="$articles"}>
                <{foreach from=$articles item=article}>
                    <div class="article-item">
                        <h3><a href="<{:url('Article/detail', ['id' => $article.id])}>"><{$article.title}></a></h3>
                        <p class="meta">
                            作者：<{$article.author}> | 
                            时间：<{$article.create_time|date='Y-m-d'}> | 
                            阅读：<{$article.view_count}>
                        </p>
                        <div class="summary"><{$article.content|substr:0:200}>...</div>
                    </div>
                <{/foreach}>
            <{else}>
                <div class="no-data">暂无文章</div>
            <{/notempty}>
        </div>
        
        <div class="pagination">
            <{$page_html|raw}>
        </div>
    </div>
<{/block}>
```

## 9. 总结

Candy框架的模板引擎提供了丰富的功能和灵活的语法，能够满足各种视图层的需求。通过合理使用模板引擎的功能，可以提高开发效率，增强代码的可维护性，同时确保输出的安全性。
