# Candy框架路由使用说明

## 一、路由的基本配置

### 1.1 全局路由配置

在项目的配置文件中，可以设置以下路由相关参数：

```php
// URL模式：1=PATHINFO模式（默认），0=普通参数模式
C('URL_MODEL', 1);

// URL分隔符，默认'/'
C('URL_DEPR', '/');

// URL伪静态后缀，默认'.html'
C('URL_HTML_SUFFIX', '.html');

// 开启路由功能
C('URL_ROUTER_ON', true);

// 静态路由映射规则
C('URL_MAP_RULES', [
    '/about' => 'Home/Index/about',
    '/contact' => 'Home/Index/contact'
]);

// 动态路由规则
C('URL_ROUTE_RULES', [
    'user/:id' => 'User/read',
    'news/:year/:month' => 'News/archive'
]);
```

### 1.2 路由配置文件

**层级约定（互不污染）**

| 文件 | 角色 |
|------|------|
| `Source/Inc/Route.inc.php` | **全局兜底**（各应用未声明时的默认） |
| `Source/Inc/{App}Route.inc.php` | **应用覆盖/叠加**（如 `AdminRoute` → `.shtml`，`HomeRoute` → `.html`） |
| `Addons/{Name}/route.php` | Addon 覆盖 |

框架在路由匹配前会窥探 PATH 首段（或域名绑定 / `C('APP')`）并先合并应用配置，再剥后缀、匹配规则，避免「改全局后缀冲掉 Admin」。

可以在 `Application/Config/route.php` 或上述文件中配置：

```php
return [
    'URL_ROUTER_ON' => true,
    'URL_MAP_RULES' => [
        // 静态路由规则
    ],
    'URL_ROUTE_RULES' => [
        // 动态路由规则
    ]
];
```

`URL_HTML_SUFFIX`、`URL_MODEL` 等标量由应用配置**覆盖**全局；`URL_MAP_RULES` / `URL_ROUTE_RULES` 为**数组合并叠加**。

## 二、路由类型及使用方法

### 2.1 静态路由（URL映射）

静态路由是最简单的路由类型，直接将一个URL路径映射到指定的控制器/操作：

**配置方式**：
```php
C('URL_MAP_RULES', [
    '/about' => 'Home/Index/about',
    '/contact' => 'Home/Index/contact',
    '/api/v1/users' => 'Api/v1/User/index'
]);
```

**访问示例**：
- `/about` → 映射到 `Home/Index/about`
- `/contact` → 映射到 `Home/Index/contact`

### 2.2 动态路由（规则路由）

动态路由允许在路由规则中使用动态变量，用于匹配可变的URL部分：

**基本语法**：
```
路由规则中以冒号(:)开头的部分表示动态变量
```

**配置示例**：
```php
C('URL_ROUTE_RULES', [
    // 基本动态路由
    'user/:id' => 'User/read',
    
    // 多个动态变量
    'news/:year/:month/:day' => 'News/archive',
    
    // 带函数过滤的动态变量
    'article/:id|intval' => 'Article/read',
    
    // 带参数的路由
    'product/:id' => 'Product/detail?id=:1',
    
    // 数组形式的路由定义
    'category/:id' => ['Category/index', ['ext' => 'html', 'method' => 'get']]
]);
```

**访问示例**：
- `/user/123` → 映射到 `User/read`，参数 `id=123`
- `/news/2023/10/15` → 映射到 `News/archive`，参数 `year=2023&month=10&day=15`
- `/article/456` → 映射到 `Article/read`，参数 `id=456`（已通过intval函数过滤）

### 3.3 正则路由

正则路由提供更灵活的路由匹配能力，使用正则表达式来匹配URL路径：

**基本语法**：
```
路由规则以正斜杠(/)开头，表示这是一个正则表达式
```

**配置示例**：
```php
C('URL_ROUTE_RULES', [
    // 匹配数字ID的用户详情
    '/^user\/(\d+)$/' => 'User/read?id=:1',
    
    // 匹配用户名的用户资料
    '/^profile\/([a-zA-Z0-9_]+)$/' => 'User/profile?username=:1',
    
    // 匹配文章ID的文章详情（支持html后缀）
    '/^article\/([0-9]+)\.html$/' => 'Article/read?id=:1'
]);
```

**访问示例**：
- `/user/123` → 映射到 `User/read`，参数 `id=123`
- `/profile/john_doe` → 映射到 `User/profile`，参数 `username=john_doe`
- `/article/456.html` → 映射到 `Article/read`，参数 `id=456`

### 4.4 闭包路由

闭包路由允许直接在路由规则中定义处理逻辑，无需创建控制器：

**配置示例**：
```php
C('URL_ROUTE_RULES', [
    // 基本闭包路由
    'hello/:name' => function($name) {
        return "Hello, {$name}!";
    },
    
    // 正则闭包路由
    '/^greeting\/([a-zA-Z]+)$/' => function($name) {
        return "Greetings, {$name}!";
    }
]);
```

**访问示例**：
- `/hello/World` → 输出 "Hello, World!"
- `/greeting/John` → 输出 "Greetings, John!"

## 三、路由参数处理

### 3.1 参数类型限制

可以在动态路由中对参数类型进行限制：

```php
C('URL_ROUTE_RULES', [
    // 只匹配数字ID
    'user/:id/d' => 'User/read',
    
    // 只匹配字母和数字的用户名
    'profile/:username/\w+' => 'User/profile'
]);
```

### 3.2 参数函数过滤

可以使用PHP函数对路由参数进行过滤：

```php
C('URL_ROUTE_RULES', [
    // 使用intval函数过滤ID参数
    'user/:id|intval' => 'User/read',
    
    // 使用strtoupper函数转换用户名
    'profile/:username|strtoupper' => 'User/profile'
]);
```

### 3.3 额外参数传递

可以在路由规则中传递额外参数：

```php
C('URL_ROUTE_RULES', [
    // 固定参数传递
    'admin' => 'Admin/Index/index?auth=1',
    
    // 动态参数与固定参数结合
    'user/:id' => 'User/read?type=member&id=:1'
]);
```

## 四、路由分组与命名空间

### 4.1 路由分组

路由规则可以按模块或功能进行分组：

```php
// 定义API模块的路由组
C('URL_ROUTE_RULES', [
    // API v1版本路由
    'api/v1/users' => 'Api/v1/User/index',
    'api/v1/user/:id' => 'Api/v1/User/read',
    
    // API v2版本路由
    'api/v2/users' => 'Api/v2/User/index',
    'api/v2/user/:id' => 'Api/v2/User/read'
]);
```

### 4.2 域名绑定

可以将不同的域名绑定到不同的模块：

```php
// 在全局配置中设置域名绑定
G('bindDomainList', [
    'api.example.com' => 'Api',
    'admin.example.com' => 'Admin'
]);
```

### 4.3 Api 统一前缀（`API_URL`）

多应用 PATHINFO 默认第一段为应用名（如 `/Crm/User/list.json`）。对外若需要统一挂 `api/v1` 等前缀，**不要**硬改第一段解析，而用「入站剥前缀 + 出站按需回加」：

| 方向 | 机制 | 说明 |
|------|------|------|
| **入站** | `URL_ROUTE_RULES` 一条正则 | `/api/v1/Crm/...` → 内部仍按 `Crm/...` 拆 App/Control/Action |
| **出站** | `U()` / `UrlGenerator` | Api 模式下自动追加 `API_URL.prefix`；强制绝对地址时优先 `API_URL.domain` |

配置写在全局 `Source/Inc/Route.inc.php`（框架每次请求加载；无 PATH_INFO 时也会载入配置）：

```php
return [
    'API_URL' => [
        'prefix' => 'api/v1',           // 对外路径前缀（空字符串=出站不加前缀）
        'domain' => 'api.example.com',  // 可选；仅强制加域名时优先于 HTTP_HOST
        'mode'   => false,              // true=强制出站走前缀；false=仅入站匹配 api/v* 时自动
    ],
    'URL_ROUTE_RULES' => [
        // 须置顶；目标勿以 / 开头（以 / 开头会 302，不是内部改写）
        '/^api\/v\d+\/(.+)$/' => ':1',
        // …其它业务规则…
    ],
];
```

**Api 模式何时开启**

1. 入站 PATH 匹配 `api/v{n}/…` → 自动 `C('API_URL_MODE', true)`
2. 配置 `API_URL.mode => true`，或代码里 `C('API_URL_MODE', true)`（如导出 OpenAPI 时）

**出站行为（`U()`）**

| 条件 | 结果示例 |
|------|----------|
| Api 模式 + 有 prefix | `U('Crm/User/list.json')` → `/api/v1/Crm/User/list.json` |
| 非 Api 模式（如 Admin 页） | 不加前缀，避免污染后台链接 |
| 强制绝对地址（路径以 `/` 开头、`showurl`、非 80/443 端口）且配置了 `domain`、无显式 `@域名` | `https://api.example.com/api/v1/Crm/...` |
| 显式 `U('...@other.com')` | 使用 `other.com`，**不**覆盖为 `API_URL.domain` |

**注意**

- 一条正则即可覆盖所有应用与接口，无需按项目逐条映射。
- 前缀只影响对外契约；业务层仍写 `U('App/Control/action.json')` 形态。
- 与 `bindDomainList` 并存时：显式 `@域名` > `API_URL.domain` > 当前 `HTTP_HOST`。

## 五、路由中间件

框架支持路由级别的中间件处理：

### 5.1 前置路由处理

```php
// 定义前置路由处理函数
function beforeContrastRoute($pathinfo) {
    // 在路由匹配前对路径进行预处理
    // 例如：添加语言前缀
    $lang = $_GET['lang'] ?? 'zh';
    return "/{$lang}{$pathinfo}";
}
```

### 5.2 路由后处理

在`UrlParser::parseUrl()`方法中，路由匹配完成后会执行：

```php
// 运行获取参数后中间件
Security::runMiddlewares('After');
```

## 六、路由重定向

可以配置路由重定向，支持HTTP状态码：

```php
C('URL_ROUTE_RULES', [
    // 301永久重定向
    'old-page' => ['/new-page', 301],
    
    // 302临时重定向
    'temp-page' => ['/other-page', 302],
    
    // 带参数的重定向
    'old-article/:id' => ['/new-article/:1', 301]
]);
```

## 七、路由调试与错误处理

### 7.1 路由调试

开启调试模式后，可以查看当前路由信息：

```php
// 开启调试模式
debug(1);
```

在调试信息中，可以看到当前使用的路由模式和匹配的路由规则。

### 7.2 404处理

当路由匹配失败时，可以通过`T('S404')`设置404状态和消息：

```php
// 在路由匹配失败后设置404
T('S404', '页面不存在');

// 输出404响应
headerLoading('Not Found', 404, T('S404'));
```

## 八、实际使用示例

### 8.1 基本路由配置示例

**配置文件：`Application/Config/route.php`**

```php
return [
    'URL_ROUTER_ON' => true,
    'URL_MAP_RULES' => [
        // 静态路由
        '/about' => 'Home/Index/about',
        '/contact' => 'Home/Index/contact',
        '/login' => 'Home/User/login'
    ],
    'URL_ROUTE_RULES' => [
        // 动态路由
        'user/:id' => 'User/read',
        'news/:year/:month' => 'News/archive',
        
        // 带参数的路由
        'product/:id' => 'Product/detail?id=:1',
        
        // 正则路由
        '/^article\/([0-9]+)\.html$/' => 'Article/read?id=:1',
        '/^profile\/([a-zA-Z0-9_]+)$/' => 'User/profile?username=:1',
        
        // 闭包路由
        'hello/:name' => function($name) {
            return json_encode(['message' => "Hello, {$name}!"]);
        },
        
        // 重定向路由
        'old-article/:id' => ['/article/:1.html', 301]
    ]
];
```

### 8.2 控制器中的路由参数获取

在控制器中，可以通过`$_GET`或`Request`类获取路由参数：

```php
<?php
namespace Home\Controller;

use Candy\Core\Action;

class UserControl extends Action {
    
    public function read() {
        // 获取路由参数
        $id = $_GET['id'];
        
        // 使用路由参数查询数据
        $user = Candy\DB\Connection::getInstance()->table('User')->find($id);
        
        // 渲染视图
        $this->assign('user', $user);
        $this->display();
    }
    
    public function profile() {
        // 获取用户名参数
        $username = $_GET['username'];
        
        // 查询用户资料
        $user = Candy\DB\Connection::getInstance()->table('User')->where(['username' => $username])->find();
        
        // 渲染视图
        $this->assign('user', $user);
        $this->display();
    }
}
```

## 九、高级路由功能

### 9.1 API路由

框架支持将路由配置为API模式，返回JSON或XML格式数据：

```php
C('URL_ROUTE_RULES', [
    'api/user/:id' => ['Api/User/read', ['ext' => 'json']],
    'api/news' => ['Api/News/index', ['ext' => 'xml']]
]);
```

### 9.2 Workerman模式兼容

框架支持在Workerman模式下使用路由系统：

```php
// 在 Workerman Rpc 模式下，路由参数通过 G('rpc') 传递（兼容旧键 jsonrpc）
G('rpc', [
    'm' => 'User',
    'a' => 'read',
    'id' => 123
]);
```

## 十、路由最佳实践

1. **使用静态路由**：对于固定的URL路径，优先使用静态路由以提高性能
2. **限制参数类型**：使用动态路由时，尽量限制参数类型和格式
3. **合理使用正则路由**：正则路由虽然灵活，但性能相对较低，应谨慎使用
4. **路由分组**：按模块或功能对路由进行分组，提高代码可读性和维护性
5. **版本控制**：对于API路由，使用版本号进行管理
6. **重定向管理**：使用301重定向处理URL变更，有利于SEO和用户体验
7. **调试与监控**：在开发阶段开启调试模式，监控路由匹配情况

## 十一、常见问题与解决方案

### 11.1 路由不生效

**问题**：配置了路由规则，但访问时不生效

**解决方案**：
- 检查是否开启了路由功能：`C('URL_ROUTER_ON')` 应为 `true`
- 检查路由规则格式是否正确
- 检查URL模式是否正确：`C('URL_MODEL')` 应为 `1`（PATHINFO模式）
- 清除缓存后重试

### 11.2 路由冲突

**问题**：多个路由规则都匹配同一个URL路径

**解决方案**：
- 调整路由规则的顺序，优先级高的规则放在前面
- 使用更具体的路由规则
- 使用正则路由精确匹配

### 11.3 参数获取错误

**问题**：路由参数无法正确获取

**解决方案**：
- 检查路由规则中的参数名是否与控制器中使用的参数名一致
- 检查参数过滤函数是否正确
- 检查URL路径中的参数顺序是否与路由规则一致

## 总结

Candy框架的路由系统提供了丰富的功能，支持静态路由、动态路由、正则路由和闭包路由等多种路由类型，同时支持路由参数验证、过滤、重定向等高级功能。合理配置和使用路由系统，可以提高应用的性能、可读性和维护性。
