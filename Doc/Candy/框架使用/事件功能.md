# Candy框架事件处理系统

## 1. 事件系统概述

Candy框架的事件处理系统实现了观察者设计模式，提供了灵活的事件注册、分发和监听机制。该系统允许组件之间通过事件进行松耦合通信，提高了代码的可维护性和扩展性。

### 主要特性
- 支持精确事件和通配符事件监听（如：`class.*`）
- 提供统一的事件触发接口
- 支持事件回调的自动解析和执行
- 支持事件响应的收集和处理
- 实现了事件缓存管理机制

## 2. 核心概念

### 2.1 事件（Event）
事件是系统中发生的特定动作或状态变化，通常由事件名称标识。事件名称采用点分命名空间格式，如：`user.login`、`system.shutdown`。

### 2.2 监听器（Listener）
监听器是响应特定事件的回调函数或方法，当事件被触发时执行相应的逻辑。

### 2.3 精确事件
精确事件是指完全匹配事件名称的监听，如：`user.login`只会响应名为`user.login`的事件。

### 2.4 通配符事件
通配符事件使用`*`作为名称后缀，可以响应一类事件，如：`user.*`可以响应`user.login`、`user.logout`等所有以`user.`开头的事件。

## 3. 事件处理核心类

### 3.1 Event类
`Event`类是事件处理系统的核心，负责管理和分发所有事件。

**命名空间**：`Candy\Core`

**文件位置**：`/Candy/Core/Event.class.php`

**主要属性**：
- `$events`：事件配置存储数组
- `$eventMap`：精确事件监听器映射
- `$prefixEventMap`：前缀事件监听器映射
- `$id`：监听器ID计数器
- `$eventConfig`：事件配置对象缓存

## 4. 主要方法

### 4.1 事件触发方法

#### 4.1.1 emit
触发指定名称的事件

```php
public static function emit(string $event_name, mixed $data, bool $halt = false, string $type = 'emit'): ?array
```

**参数**：
- `$event_name`：事件名称
- `$data`：传递给事件监听器的数据
- `$halt`：是否在接收到第一个非空响应时停止执行
- `$type`：事件触发类型，默认为'emit'

**返回值**：
- 当`$halt`为`true`时，返回第一个非空响应或`null`
- 当`$halt`为`false`时，返回所有监听器的响应数组

#### 4.1.2 dispatch
分发指定名称的事件（`emit`方法的别名）

```php
public static function dispatch(string $event_name, mixed $data, bool $halt = false, string $type = 'dispatch'): array|null
```

**参数**：
- `$event_name`：事件名称
- `$data`：传递给事件监听器的数据
- `$halt`：是否在接收到第一个非空响应时停止执行
- `$type`：事件触发类型，默认为'dispatch'

**返回值**：
- 与`emit`方法相同

### 4.2 事件监听器管理方法

#### 4.2.1 getListeners
获取指定事件的监听器列表

```php
public static function getListeners(string $event_name, string $type = 'dispatch'): array
```

**参数**：
- `$event_name`：事件名称
- `$type`：事件类型，默认为'dispatch'

**返回值**：
- 事件监听器数组，按ID排序

#### 4.2.2 list
获取所有已注册的事件监听器列表

```php
public static function list(): array
```

**返回值**：
- 已注册的事件监听器列表，格式为：`[id => [事件名称, 监听器]]`

#### 4.2.3 hasListener
检查指定事件是否有监听器

```php
public static function hasListener(string $event_name): bool
```

**参数**：
- `$event_name`：事件名称

**返回值**：
- 如果事件有监听器则返回`true`，否则返回`false`

### 4.3 事件配置和缓存方法

#### 4.3.1 clearCache
清除事件缓存

```php
public static function clearCache(): void
```

**功能**：
- 重置所有与事件相关的静态变量，包括事件配置、事件映射和前缀事件映射
- 强制系统重新从配置文件加载事件定义

## 5. 事件配置方式

事件配置文件位于`/www/wwwroot/Candy/Candy/Config/Event.php`，格式如下：

```php
return [
    // 精确事件配置
    'user.login' => [
        ['App\Event\UserEvent', 'onLogin']
    ],
    // 通配符事件配置
    'user.*' => [
        ['App\Event\UserEvent', 'onAny']
    ]
];
```

## 6. 使用示例

### 6.1 配置事件监听器

在`Event.php`配置文件中注册事件监听器：

```php
return [
    'user.register' => [
        ['App\Event\UserListener', 'onRegister']
    ],
    'user.*' => [
        ['App\Event\UserListener', 'onAnyUserEvent']
    ]
];
```

### 6.2 创建事件监听器类

```php
namespace App\Event;

class UserListener {
    // 监听用户注册事件
    public function onRegister($data, $event_name) {
        // 处理用户注册逻辑
        echo "用户注册事件触发，用户ID：" . $data['user_id'];
        return true;
    }
    
    // 监听所有用户相关事件
    public function onAnyUserEvent($data, $event_name) {
        // 处理通用用户事件逻辑
        echo "用户事件触发：" . $event_name;
    }
}
```

### 6.3 触发事件

```php
// 在控制器或其他地方触发事件

// 导入Event类
use Candy\Core\Event;

// 触发用户注册事件
$data = ['user_id' => 123, 'username' => 'testuser'];

// 方法1：使用emit触发事件
$responses = Event::emit('user.register', $data);

// 方法2：使用dispatch触发事件（与emit功能相同）
$responses = Event::dispatch('user.register', $data);

// 使用halt参数，在第一个非空响应时停止执行
$response = Event::emit('user.register', $data, true);
```

### 6.4 获取已注册事件

```php
// 获取所有已注册事件
$all_events = Event::list();

// 检查特定事件是否有监听器
if (Event::hasListener('user.login')) {
    echo "user.login事件有监听器";
}

// 获取特定事件的监听器
$listeners = Event::getListeners('user.login');
```

### 6.5 清除事件缓存

```php
// 清除事件缓存，强制重新加载配置
Event::clearCache();
```

## 7. 高级用法

### 7.1 通配符事件

通配符事件允许监听一类相关事件，使用`*`作为事件名称后缀：

```php
// 配置文件中
return [
    'system.*' => [
        ['App\Event\SystemListener', 'onSystemEvent']
    ]
];

// 触发事件
echo Event::emit('system.start', ['time' => time()]); // 会触发system.*监听器
echo Event::emit('system.shutdown', []); // 也会触发system.*监听器
```

### 7.2 事件响应处理

事件监听器可以返回响应数据，这些数据会被收集并返回给事件触发者：

```php
// 监听器
public function onUserLogin($data) {
    return ['status' => 'success', 'message' => '登录成功'];
}

// 触发事件并获取响应
$responses = Event::emit('user.login', ['username' => 'test']);

// 处理响应
foreach ($responses as $response) {
    if ($response['status'] === 'success') {
        echo $response['message'];
    }
}
```

## 8. 最佳实践

1. **事件命名规范**：使用点分命名空间格式，如`module.action`
2. **单一职责**：每个监听器只处理一个特定功能
3. **避免阻塞**：事件监听器应避免执行耗时操作，影响系统性能
4. **错误处理**：在监听器中适当处理异常，避免影响其他监听器执行
5. **避免循环依赖**：事件触发和监听应避免形成循环依赖

## 9. 性能优化

- 事件监听器会被缓存，减少重复加载和解析开销
- 使用通配符事件可以减少配置数量，但可能增加事件匹配开销
- 对于高频触发的事件，应优化监听器的执行效率

## 10. 调试与日志

事件系统会自动记录错误信息到日志文件，日志路径为：`/Log/event-YYYY-MM-DD.log`

可以通过查看日志文件了解事件触发和执行情况，便于调试和问题排查。
