# Candy框架Debug调试类文档

## 1. 类概述

Debug类是Candy框架的核心调试组件，负责框架的错误捕获、异常处理、调试信息收集与展示，以及性能监控等功能。该类采用静态方法设计，提供了全面的调试支持，帮助开发者快速定位和解决问题。

## 2. 核心功能

Debug类主要提供以下核心功能：

- **错误与异常处理**：捕获并处理PHP运行时错误、用户自定义错误和异常
- **调试信息收集**：分类存储不同类型的调试信息（SQL语句、加载文件、路径信息等）
- **性能监控**：提供计时器功能，用于测量代码执行时间
- **调试信息展示**：根据执行环境（CLI/Web）以不同方式展示格式化的调试信息
- **脚本关闭处理**：捕获脚本执行结束时的致命错误

## 3. 静态属性

Debug类使用多个静态属性来存储不同类型的调试信息：

| 属性名 | 类型 | 作用 |
|-------|------|------|
| `$includefile` | array | 已加载文件列表，格式：`['framework' => [...], 'app' => [...]]` |
| `$application` | array | 应用程序相关的调试信息 |
| `$info` | array | 一般调试信息 |
| `$sqls` | array | 执行过的SQL语句记录 |
| `$paths` | array | 与路径相关的调试信息 |
| `$errors` | array | 捕获到的错误信息 |
| `$timers` | array | 计时器数据，格式：`['timer_name' => start_time]`（私有） |
| `$msg` | array | 错误类型映射表，将PHP错误常量映射为可读名称（私有） |

## 4. 主要方法

### 4.1 初始化方法

#### start()
```php
public static function start(): void
```

**功能**：初始化调试器，在脚本开始处调用。

**主要操作**：
1. 启动默认计时器
2. 设置自定义错误处理函数
3. 设置自定义异常处理函数
4. 注册脚本关闭处理函数
5. 根据调试模式配置错误报告级别
6. 在CLI模式下清理静态数据数组

**使用示例**：
```php
Debug::start();
```

### 4.2 错误与异常处理

#### catcher()
```php
public static function catcher(int $errno, string $errstr, string $errfile, int $errline): void
```

**功能**：PHP错误发生时自动调用，捕获并记录错误信息。

**参数**：
- `$errno`：错误级别（如E_WARNING、E_NOTICE等）
- `$errstr`：错误描述信息
- `$errfile`：发生错误的文件路径
- `$errline`：发生错误的行号

**处理逻辑**：
- 忽略特定类型的错误（如open_basedir限制警告）
- 调试模式下：将错误信息添加到调试消息队列
- 非调试模式下：将错误记录到日志文件

#### exception()
```php
public static function exception($e): void
```

**功能**：PHP异常发生时自动调用，处理并展示异常信息。

**参数**：
- `$e`：异常对象

**处理逻辑**：
- 处理文件路径，移除框架路径前缀
- 根据执行环境（Web/CLI）以不同方式展示异常信息

#### shutdown()
```php
public static function shutdown(): void
```

**功能**：脚本执行结束时自动调用，捕获并处理未被自定义错误处理器捕获的致命错误。

**处理逻辑**：
- 使用`error_get_last()`获取最后一个错误信息
- 处理文件路径和错误消息
- 根据执行环境展示格式化的错误信息

### 4.3 调试信息管理

#### addMsg()
```php
public static function addMsg(string $msg, int $type = 0): void
```

**功能**：根据不同类型将调试消息添加到相应的存储数组中，仅在调试模式下有效。

**参数**：
- `$msg`：调试消息字符串，支持HTML标签
- `$type`：消息类型（默认0）
  - 0：一般调试信息（存储在$info）
  - 1：应用文件信息（存储在$includefile['app']）
  - 2：SQL语句信息（存储在$sqls）
  - 3：路径信息（存储在$paths）
  - 4：错误信息（存储在$errors）
  - 5：框架文件信息（存储在$includefile['framework']）
  - 6：应用程序信息（存储在$application）

**使用示例**：
```php
// 添加一般调试信息
Debug::addMsg('用户登录成功', 0);

// 添加SQL语句
Debug::addMsg('SELECT * FROM users WHERE id = 1', 2);

// 添加框架文件信息
Debug::addMsg('<b>Model</b>类', 5);
```

#### showMessage()
```php
public static function showMessage(string $msg, string $type = '', string $detailed = ''): void
```

**功能**：根据执行环境以不同方式展示格式化的错误信息。

**参数**：
- `$msg`：简洁的错误消息
- `$type`：错误类型标识（如'Exception'、'Shutdown'等）
- `$detailed`：详细的错误信息（通常包含文件路径和行号）

**处理逻辑**：
- Web环境下：直接输出错误信息
- CLI环境下：
  - 普通页面：使用模板展示详细错误信息
  - API接口：返回JSON或XML格式的错误数据

### 4.4 性能计时

#### startTimer()
```php
public static function startTimer(string $name = 'default'): void
```

**功能**：为指定名称的计时器记录开始时间点。

**参数**：
- `$name`：计时器名称（默认'default'）

**使用示例**：
```php
// 开始默认计时器
Debug::startTimer();

// 开始自定义名称的计时器
Debug::startTimer('database_query');
```

#### getTimer()
```php
public static function getTimer(string $name = 'default'): float
```

**功能**：返回指定名称计时器从开始到现在的运行时间（毫秒）。

**参数**：
- `$name`：计时器名称（默认'default'）

**返回值**：执行时间（毫秒），精确到小数点后两位

**使用示例**：
```php
// 获取默认计时器的执行时间
$time = Debug::getTimer();
echo "脚本执行时间：{$time}ms";

// 获取自定义计时器的执行时间
$dbTime = Debug::getTimer('database_query');
echo "数据库查询时间：{$dbTime}ms";
```

#### spent()
```php
public static function spent(): float
```

**功能**：获取默认计时器的运行时间（毫秒），是`getTimer('default')`的便捷封装。

**返回值**：执行时间（毫秒），精确到小数点后两位

**使用示例**：
```php
// 获取脚本执行时间
$time = Debug::spent();
echo "脚本执行时间：{$time}ms";
```

### 4.5 异常格式化

#### exceptionFormat()
```php
public static function exceptionFormat(\Throwable $exception): void
```

**功能**：将异常信息和堆栈跟踪转换为更友好、更易读的格式。

**参数**：
- `$exception`：异常对象

**处理逻辑**：
- 输出异常消息和基本信息
- 格式化堆栈跟踪，处理特殊文件路径前缀
- 主要用于开发环境中调试复杂的异常情况

**使用示例**：
```php
try {
    // 可能抛出异常的代码
} catch (\Exception $e) {
    Debug::exceptionFormat($e);
}
```

## 4. 调试模式配置

Debug类的行为受框架调试模式影响，通过以下方式配置：

### 4.1 调试模式开启/关闭

```php
// 在配置文件中设置调试模式
C('DEBUG', true); // 开启调试模式
C('DEBUG', false); // 关闭调试模式
```

### 4.2 错误报告级别

Debug类会根据调试模式自动设置合适的错误报告级别：

- **调试模式开启**：`error_reporting(E_ALL);`（显示所有错误）
- **调试模式关闭**：`error_reporting(E_ALL^E_WARNING^E_NOTICE);`（忽略警告和提醒）

## 5. 调试工作流程

### 5.1 初始化流程

1. 调用`Debug::start()`初始化调试器
2. 启动默认计时器
3. 设置错误和异常处理函数
4. 注册脚本关闭处理函数

### 5.2 错误与异常处理流程

1. PHP错误发生 → 调用`catcher()`方法
2. PHP异常发生 → 调用`exception()`方法
3. 脚本执行结束 → 调用`shutdown()`方法检查致命错误
4. 根据调试模式和执行环境展示错误信息

### 5.3 调试信息收集流程

1. 框架各组件调用`addMsg()`添加调试信息
2. 信息根据类型分类存储到不同静态属性中
3. 脚本执行结束时统一处理和展示

## 6. 常见使用场景

### 6.1 性能监控

```php
// 监控数据库查询性能
Debug::startTimer('db_query');
// 执行数据库查询
$result = $db->query('SELECT * FROM users');
$time = Debug::getTimer('db_query');
Debug::addMsg("数据库查询耗时：{$time}ms", 0);

// 监控整个脚本执行时间
echo "脚本执行总时间：" . Debug::spent() . "ms";
```

### 6.2 调试信息记录

```php
// 记录SQL语句
$sql = 'INSERT INTO users (name, email) VALUES (?, ?)';
Debug::addMsg($sql, 2);

// 记录文件加载信息
Debug::addMsg('<b>UserController</b>类', 1);

// 记录应用程序信息
Debug::addMsg("当前用户ID：{$userId}", 6);
```

### 6.3 自定义错误处理

```php
// 在应用代码中手动触发错误
if ($errorCondition) {
    Debug::addMsg("自定义错误：参数无效", 4);
}

// 捕获并处理异常
try {
    // 可能抛出异常的代码
} catch (\Exception $e) {
    Debug::exceptionFormat($e);
}
```

## 7. 高级功能与注意事项

### 7.1 强制刷新缓存

在调试过程中，可以通过URL参数强制刷新框架缓存：

```
http://yourdomain.com/?reflush
```

### 7.2 环境适配

Debug类会自动检测执行环境（Web/CLI），并以不同方式展示调试信息：

- **Web环境**：直接输出HTML格式化的错误信息
- **CLI环境**：输出纯文本格式的错误信息，适合命令行调试

### 7.3 API接口支持

在API接口开发中，Debug类支持JSON和XML两种数据格式的错误响应：

```xml
// JSON格式响应
{"status":0,"msg":"错误信息","sessionid":"abc123"}

// XML格式响应
<root>
  <status>0</status>
  <msg>错误信息</msg>
  <sessionid>abc123</sessionid>
</root>
```

### 7.4 注意事项

1. **性能影响**：调试模式会收集大量调试信息，可能影响应用性能，生产环境建议关闭调试模式
2. **错误信息安全性**：调试模式下会展示详细错误信息，包含文件路径和代码行号，生产环境应关闭以避免信息泄露
3. **自定义错误类型**：可以根据需要扩展`$msg`属性，添加自定义错误类型映射
4. **资源清理**：在长时间运行的脚本中，注意定期清理调试信息数组，避免内存溢出

## 8. 总结

Candy框架的Debug类提供了全面的调试支持，帮助开发者快速定位和解决问题。通过合理使用其提供的错误处理、调试信息收集和性能监控功能，可以显著提高开发效率和代码质量。在开发环境中充分利用Debug类的功能，在生产环境中关闭调试模式以保证性能和安全性，是最佳实践。
