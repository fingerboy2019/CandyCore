# 日志使用说明

## 1. 概述

日志管理系统是Candy框架的重要组成部分，提供统一的日志记录、读取和管理功能。它支持多种日志级别，自动格式化日志内容，支持数组、对象和异常等多种数据类型的记录，并提供HTML友好的日志展示方式。

### 1.1 主要功能

- 支持6种日志级别记录（DEBUG、INFO、WARN、ERROR、FATAL、SQL_ERROR）
- 自动创建日志目录和按日期命名的日志文件
- 异常信息详细记录（包括完整堆栈跟踪）
- 支持自定义日志文件路径
- 支持HTML表格格式化展示日志
- 自动处理文件句柄的打开和关闭，避免资源泄漏

### 1.2 应用场景

- 系统运行状态监控
- 错误追踪和调试
- SQL查询记录和错误分析
- 用户操作行为记录
- 系统事件记录

## 2. 日志级别

| 级别代码 | 级别名称   | 说明                                   |
|---------|----------|----------------------------------------|
| -1      | 无级别    | 不显示级别标识                         |
| 0       | DEBUG    | 调试信息，用于开发阶段                  |
| 1       | INFO     | 一般信息，记录系统运行状态              |
| 2       | WARN     | 警告信息，可能存在潜在问题              |
| 3       | ERROR    | 错误信息，系统发生错误但可继续运行      |
| 4       | FATAL    | 致命错误，系统无法继续运行              |
| 5       | SQL_ERROR| SQL错误，专门用于记录数据库操作错误     |

## 3. 配置说明

### 3.1 日志存储路径

日志默认存储在配置的`LOGPATH`目录下，该配置项可以在框架配置文件中设置。

```php
// 默认日志路径格式
$logPath = C('LOGPATH') . date("Y-m-d") . '.log';
```

### 3.2 其他配置

- `APP_INIT_STATUS`: 系统初始化状态，只有当此配置为true时，日志系统才会工作
- `actinfo.log`: 控制是否记录操作日志，用于addLogs()函数

## 4. API接口

### 4.1 Log类核心方法

#### 4.1.1 记录日志

```php
public static function input(mixed $data, int $type = 0, ?string $path = null): void
```

**参数说明**：
- `$data`: 要记录的数据，可以是字符串、数组、对象或异常
- `$type`: 日志级别，默认值为0（DEBUG）
- `$path`: 日志文件路径，为空时使用默认路径

**示例**：
```php
// 记录调试信息
\Candy\Core\Log::input('调试信息', 0);

// 记录错误信息
\Candy\Core\Log::input('数据库连接失败', 3);

// 记录SQL错误
\Candy\Core\Log::input($sqlError, 5);

// 记录异常信息
\Candy\Core\Log::input($exception);

// 记录到自定义路径
\Candy\Core\Log::input('特殊日志', 1, C('LOGPATH') . 'special.log');
```

#### 4.1.2 读取日志

```php
public static function read(?string $path = null, bool $display = false): mixed
```

**参数说明**：
- `$path`: 日志文件路径，为空时使用默认路径
- `$display`: 是否返回HTML表格格式，默认为false（返回数组）

**返回值**：
- 当`$display`为false时，返回日志内容数组
- 当`$display`为true时，返回HTML表格格式的日志内容

**示例**：
```php
// 读取默认日志
$logContent = \Candy\Core\Log::read();

// 读取指定路径的日志
$errorLog = \Candy\Core\Log::read('./logs/error.log');

// 读取日志并直接显示为HTML表格
$htmlLog = \Candy\Core\Log::read('./logs/system.log', true);
echo $htmlLog;
```

## 5. 全局函数

为了方便使用，框架提供了以下全局函数作为Log类的包装器：

### 5.1 writeLog()

用于记录日志的快捷函数，内部调用`\Candy\Core\Log::input()`方法。

```php
function writeLog(string $message, int $type = 0, string $path = ''): void
```

**参数说明**：
- `$message`: 日志消息
- `$type`: 日志级别，默认值为0（DEBUG）
- `$path`: 日志文件路径，为空时使用默认路径

**示例**：
```php
// 记录普通日志
writeLog('用户登录成功: ' . $username);

// 记录错误日志
writeLog('数据库连接失败: ' . mysqli_error($link), 1);

// 记录到自定义路径
writeLog('定时任务执行结果', 0, './logs/cron.log');
```

### 5.2 readLog()

用于读取日志的快捷函数，内部调用`\Candy\Core\Log::read()`方法。

```php
function readLog(?string $path = null, bool $display = false): string
```

**参数说明**：
- `$path`: 日志文件路径，为空时使用默认路径
- `$display`: 是否返回HTML表格格式，默认为false

**示例**：
```php
// 读取默认日志
$logContent = readLog();

// 读取指定路径的日志
$errorLog = readLog('./logs/error.log');

// 读取日志并直接显示
$displayLog = readLog('./logs/system.log', true);
```

### 5.3 addLogs()

框架提供的日志记录接口，可以被应用层重写以提供自定义的日志记录逻辑。默认实现为空函数。

```php
function addLogs(): void
```

**使用场景**：
- 可以在应用中重写此函数，实现自定义的日志记录逻辑
- 框架会在系统初始化完成后自动调用此函数（如果`actinfo.log`配置为true）

## 6. 日志使用示例

### 6.1 基本日志记录

```php
// 使用全局函数记录普通信息
writeLog('系统启动完成', 1);

// 使用Log类记录调试信息
\Candy\Core\Log::input('用户请求参数: ' . json_encode($_REQUEST), 0);
```

### 6.2 异常日志记录

```php
try {
    // 可能抛出异常的代码
    $db->query($invalidSql);
} catch (PDOException $e) {
    // 记录异常信息，自动包含堆栈跟踪
    writeLog($e, 5);
    // 或者使用Log类
    // \Candy\Core\Log::input($e, 5);
}
```

### 6.3 自定义路径日志

```php
// 记录到自定义路径的日志文件
writeLog('管理员操作日志', 1, C('LOGPATH') . 'admin-operations.log');

// 使用Log类
// \Candy\Core\Log::input('特殊操作日志', 1, C('LOGPATH') . 'special.log');
```

### 6.4 日志读取与展示

```php
// 读取日志并处理
$logs = readLog();
foreach ($logs as $logLine) {
    // 处理日志行
    echo $logLine . '<br>';
}

// 直接在浏览器中显示日志
$htmlLog = readLog('./logs/system.log', true);
echo $htmlLog;
```

### 6.5 系统事件日志

```php
// 记录系统事件，不显示级别标识
\Candy\Core\Log::input('用户登录: ' . $username, -1, C('LOGPATH') . 'events-' . date('Y-m-d') . '.log');
```

## 7. 最佳实践

### 7.1 日志记录建议

1. **选择合适的日志级别**：根据信息的重要性选择合适的日志级别，避免所有日志都使用同一级别
2. **记录关键信息**：记录足够的上下文信息，如用户ID、请求参数、时间戳等，便于问题定位
3. **避免记录敏感信息**：不要在日志中记录密码、信用卡号等敏感信息
4. **控制日志量**：避免在循环中记录大量日志，影响系统性能
5. **使用异常记录**：对于异常情况，直接记录异常对象，自动包含完整的堆栈跟踪信息

### 7.2 日志文件管理

1. **定期清理旧日志**：设置日志保留策略，定期清理过期日志文件
2. **分模块记录**：对不同功能模块使用不同的日志文件，便于管理和分析
3. **监控日志大小**：避免单个日志文件过大，可以按大小分割日志文件
4. **备份重要日志**：对重要的日志文件进行定期备份，防止数据丢失

### 7.3 性能考虑

1. **生产环境调整**：在生产环境中，可以适当提高日志级别，减少日志量
2. **避免频繁IO操作**：日志系统已经优化了文件句柄的使用，但仍应避免过于频繁的日志记录
3. **异步日志**：对于高并发场景，可以考虑使用异步日志记录方式

## 8. 注意事项

1. **日志类是final类**：Log类是一个final类，不能被继承
2. **日志路径配置**：确保LOGPATH配置正确，并且有足够的写入权限
3. **系统初始化状态**：系统只有在APP_INIT_STATUS为true时才会记录日志
4. **SQL错误处理**：对于SQL错误和PDO异常，系统会自动记录更详细的信息
5. **资源类型处理**：资源类型的数据会被转换为通用描述文本
6. **文件句柄管理**：日志系统会自动关闭文件句柄，无需手动管理

## 9. 代码示例

### 9.1 完整的日志使用示例

```php
<?php

// 记录系统启动信息
writeLog('系统启动完成', 1);

try {
    // 连接数据库
    $db = new PDO('mysql:host=localhost;dbname=mydb', 'username', 'password');
    writeLog('数据库连接成功', 1);
    
    // 执行查询
    $stmt = $db->query('SELECT * FROM users');
    $users = $stmt->fetchAll();
    writeLog('查询到 ' . count($users) . ' 个用户记录', 1);
    
    // 执行可能出错的操作
    $invalidStmt = $db->query('SELECT * FROM non_existent_table');
    
} catch (PDOException $e) {
    // 记录数据库错误，自动包含堆栈跟踪
    writeLog($e, 5);
    
    // 记录错误上下文
    writeLog('错误发生在数据库操作过程中，用户ID: ' . $_SESSION['user_id'], 3);
}

// 记录用户操作
writeLog('用户 ' . $_SESSION['username'] . ' 执行了数据导出操作', 1);

// 读取并显示日志（开发环境）
if (C('APP_DEBUG')) {
    $todayLog = readLog(null, true);
    echo $todayLog;
}
```

### 9.2 自定义日志记录函数

```php
<?php

// 重写addLogs函数，实现自定义日志逻辑
function addLogs() {
    // 记录用户访问信息
    $accessInfo = [
        'ip' => getClientIp(),
        'url' => $_SERVER['REQUEST_URI'],
        'method' => $_SERVER['REQUEST_METHOD'],
        'user_agent' => $_SERVER['HTTP_USER_AGENT'],
        'timestamp' => time()
    ];
    
    writeLog(json_encode($accessInfo), 1, C('LOGPATH') . 'access-' . date('Y-m-d') . '.log');
}
```

## 10. 总结

Candy框架的日志管理系统提供了强大而灵活的日志记录功能，支持多种日志级别和数据类型，自动格式化日志内容，并提供友好的展示方式。通过合理使用日志系统，可以有效监控系统运行状态，快速定位和解决问题，提高系统的可维护性和稳定性。

在实际应用中，应根据具体需求选择合适的日志级别和记录策略，遵循最佳实践，确保日志系统既能提供足够的调试和监控信息，又不会对系统性能造成过大影响。
