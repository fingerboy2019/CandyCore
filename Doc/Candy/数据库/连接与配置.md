## 连接初始化

Candy 框架的数据库连接在应用启动时自动初始化，您可以通过全局函数或直接实例化来获取数据库连接对象。

### 获取数据库连接

#### 使用全局函数（推荐）

```php
// 获取默认数据库连接
$db = D();

// 获取指定配置的数据库连接
$db = D('other_db');
```

#### 使用D函数创建自定义配置连接（推荐）

```php
// 使用D函数创建自定义配置的数据库连接
$db = D('user', [
    'type'     => 'mysqli',
    'host'     => 'localhost',
    'user'     => 'root',
    'pass'     => 'password',
    'dbname'   => 'candy',
    'TABPREFIX'=> 'cd_',
]);

// 或使用M函数创建模型连接
$userModel = M('user', [
    'type'     => 'mysqli',
    'host'     => 'localhost',
    'user'     => 'root',
    'pass'     => 'password',
    'dbname'   => 'candy',
    'TABPREFIX'=> 'cd_',
]);
```

**注意：** 框架要求所有数据库连接必须通过D函数或M函数创建，不支持直接实例化驱动类。

## 连接池管理

框架实现了连接池管理机制，避免重复创建数据库连接，提高性能。

### 连接池特性

1. **自动连接复用**：相同配置的连接会被复用
2. **连接过期检查**：默认300秒（5分钟）内未使用的连接会被重新创建
3. **自动重连**：连接断开时自动尝试重新连接（最多3次）
4. **连接有效性验证**：CLI模式下会验证连接有效性

### 连接池配置

连接池相关配置可以在驱动类中修改：

```php
// 连接超时时间（秒）
const CONNECTION_TIMEOUT = 300;

// 最大重连尝试次数
const MAX_RECONNECT_ATTEMPTS = 3;
```

## 表操作配置

在进行数据库操作前，需要先指定要操作的表。

### 设置表名

```php
// 方法一：构造函数设置
$db = D()->setTable('user');

// 方法二：通过魔术方法访问
$db = D('user');

// 方法三：直接在查询中指定
$users = D()->select('user', '*');
```

### 表前缀

表前缀会自动添加到表名前：

```php
// 如果配置中 TABPREFIX = 'cd_'
$db = D('user'); // 实际操作的表是 cd_user
```

### 表结构缓存

框架会自动缓存表结构信息，提高性能：

1. **默认缓存位置**：`Runtime/Data/table_name.php`
2. **Redis 缓存**：如果配置了 Redis，会优先使用 Redis 缓存
3. **缓存更新**：调试模式下会实时更新缓存

## 连接参数设置

### 设置连接字符集

```php
D('user')->charset('utf8mb4');
```

### 设置查询超时

```php
D('user')->timeout(30); // 设置超时时间为30秒
```

### 设置调试模式

```php
D('user')->debug(true); // 开启调试模式
D('user')->debug(false); // 关闭调试模式
```

## 连接状态

### 检查连接

```php
// 检查是否连接成功
if (D('user')->isConnected()) {
    echo "数据库连接成功";
} else {
    echo "数据库连接失败";
}
```

### 获取连接信息

```php
// 获取数据库版本
$version = D()->dbVersion();

// 获取数据库大小
$size = D()->dbSize();

// 获取当前执行的SQL
$sql = D('user')->getLastSql();
```

## 连接切换

### 切换数据库

```php
// 方法一：直接设置
$db->dbname('other_database');

// 方法二：重新获取连接
$db = db('other_config');
```

### 切换表前缀

```php
C('TABPREFIX', 'new_'); // 切换表前缀为 new_，后续 D()/M() 连接将使用新前缀
```

## 连接关闭

框架会自动管理连接的关闭，在脚本结束时释放资源。您也可以手动关闭连接：

```php
$db->close();
```

## 连接事件

### 连接成功事件

```php
$db->onConnect(function($db) {
    // 连接成功时执行
    echo "数据库连接成功";
});
```

### 连接失败事件

```php
$db->onError(function($error) {
    // 连接失败时执行
    echo "数据库连接失败：" . $error;
});
```

## 多数据库事务

当需要在多个数据库之间执行事务时，可以使用分布式事务：

```php
// 开始事务
$db1 = db('db1');
$db2 = db('db2');

$success = true;

// 开始事务
$db1->beginTransaction();
$db2->beginTransaction();

try {
    // 执行操作
    $db1->insert('table1', ['field1' => 'value1']);
    $db2->insert('table2', ['field2' => 'value2']);
    
    // 提交事务
    $db1->commit();
    $db2->commit();
} catch (Exception $e) {
    // 回滚事务
    $db1->rollBack();
    $db2->rollBack();
    $success = false;
}

if ($success) {
    echo "事务执行成功";
} else {
    echo "事务执行失败：" . $e->getMessage();
}
```

## 连接优化建议

1. **使用长连接**：在 CLI 模式下建议使用长连接
2. **合理设置超时**：根据业务需求调整连接超时时间
3. **启用连接池**：高并发场景下启用连接池管理
4. **使用 Redis 缓存**：频繁查询的表结构使用 Redis 缓存
5. **监控连接数**：定期监控数据库连接数，避免连接泄漏

## 常见问题

### 1. 连接数过多

**症状**：数据库连接数超出最大限制

**解决方案**：
- 检查是否有连接泄漏
- 调整数据库最大连接数
- 使用连接池管理连接

### 2. 连接超时

**症状**：连接数据库超时

**解决方案**：
- 检查网络是否正常
- 增加连接超时时间
- 优化数据库服务器性能

### 3. 连接被拒绝

**症状**：数据库连接被拒绝

**解决方案**：
- 检查用户名和密码是否正确
- 检查数据库用户权限
- 检查防火墙设置

## 最佳实践

1. **单一责任**：每个数据库连接专注于一个业务模块
2. **连接复用**：避免频繁创建和关闭连接
3. **事务使用**：复杂操作使用事务保证数据一致性
4. **错误处理**：捕获并处理数据库异常
5. **性能监控**：定期监控数据库连接性能
