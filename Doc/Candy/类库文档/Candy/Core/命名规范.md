# Candy Core 命名规范

本文档约定 `Candy/Core` 及 `Candy/Func` 全局函数的命名风格，用于统一三代并存的历史命名（ThinkPHP 风格 → 缩写风格 → PSR 风格）。

## 1. 类与文件

| 类别 | 规范 | 示例 |
|------|------|------|
| 类名 | PascalCase，完整英文单词 | `UrlParser` |
| 文件名 | `{ClassName}.class.php` | `Bootstrap.class.php` |
| `class` 关键字 | 一律小写 `class` | `final class Hook` |

### 1.1 `final` 策略

| 类型 | 是否 `final` | 示例 |
|------|-------------|------|
| 框架入口 / 工具 / 门面实现类 | **是** | `Bootstrap`, `View`, `Container`, `ViewRenderer` |
| `Respond` 具体响应子类 | **是** | `Impl\Respond\Json`, `Impl\Respond\Html` |
| Cache 具体驱动 | **是** | `Impl\Cache\Redis`, `Impl\Cache\Memory` |
| 抽象基类 / 可扩展基类 | **否** | `abstract Respond`, `abstract Cache` |
| 控制器 / 中间件基类 | **否** | `Action`（`Base extends Action`）、`Security`（`JwtAuthMiddleware extends Security`） |

| Trait | PascalCase + 能力后缀 | `CsrfGuard`, `RedisKvOps` |
| 常量 | `SCREAMING_SNAKE_CASE` | `STATIC_ASSET_EXTENSIONS` |

**冻结的公开类名**（仅通过别名渐进迁移）：`Respond\Javascript`。

**易混淆类名**：写文档与 `use` 时必须全限定名区分 `Candy\Core\View`（模板引擎）与 `Candy\Core\Impl\Respond\View`（HTTP 响应）。

### 1.2 目录布局（`Core/` 仅保留两层子目录）

| 目录 | 命名空间 | 放什么 |
|------|----------|--------|
| `Core/*.class.php` | `Candy\Core` | 门面 / 抽象类：`Cache`, `View`, `Security`, `Respond`, `UrlParser` … |
| `Core/Trait/{Cache,Url,View,Security}/` | `Candy\Core\Trait\{...}` | 组合用 Trait、拆分出的协作类（`TagCompiler`, `CsrfGuard`, `PathInfoResolver`） |
| `Core/Impl/{Cache,Respond,Pack,Modifier}/` | `Candy\Core\Impl\{...}` | 需继承或替换的实现：缓存驱动、响应策略、Pack 算法、模板修饰器函数 |

**约定**：新增拆分模块优先归入 `Trait/`（能力片段）或 `Impl/`（可替换实现），避免在 `Core/` 下再建第三层业务子目录。

## 2. 方法与函数

| 可见性 | 规范 |
|--------|------|
| public | camelCase 动词开头：`parseUrl`, `loadLocale`, `verifyCsrfToken` |
| protected / private | 同 public，**禁止** public 方法使用 `_` 前缀 |
| 驱动原生层 | 双下划线仅用于 Cache 边界：`__rawGet`, `__acquireLock` |
| 布尔判断 | `is*`, `has*`, `can*`：`isStaticAssetPath` |

**冻结的全局 DSL**（不可改名）：`G()`, `C()`, `M()`, `S()`, `A()`, `L()`, `listen()`, `respond()`, `stop()`。

**新增全局函数**：camelCase 动词短语，如 `loadLocaleConfig`。

## 3. 属性与变量

| 类型 | 规范 | 反例 |
|------|------|------|
| 对象属性 | camelCase + 类型声明（新代码） | `$_cache`（已改为 `$runtimeCache`） |
| View 模板变量池 | `$viewVars` | 编译产物使用 `$this->viewVars`，`assign()` 第二参数同名 |
| 局部变量 | camelCase，短生命周期可适度缩写 | `$cainfo` → `$pathSeparatorInfo` |
| 数组业务键 | camelCase 或 snake（映射外部协议时） | `'spr'` → `'separator'` |

## 4. 配置键（`C()` / `G()`）

- 新键使用 `SCREAMING_SNAKE_CASE` 与完整单词：`COMPILE_DIR`, `URL_DELIMITER`。
- 拼写错误的旧键通过 `C()` 双读双写保持兼容（见 `global.func.php` 内别名逻辑）。

### 4.1 冻结配置键（含义说明）

以下键名**不再重命名**，新文档与注释须写清含义，避免误读缩写。

| 键名 | 读写 | 含义 | 默认值 | 主要用途 |
|------|------|------|--------|----------|
| `URL_DEPR` | `C()` | **URL 路径分隔符**（历史缩写 *depr* = delimiter）。PATH_INFO 各段之间的字符，如 `/`、`/`、`-` | `/` | `UrlParser`、`Route` 解析与还原 PATH_INFO；`global.func.php` 生成 URL；应用 `*Route.inc.php` 配置 |
| `HALLMARK` | `C()` | **千人千面标记**。为不同终端/租户/用户群加载差异化模板与钩子 | `null`（关闭） | `View` 优先 `模板名_{HALLMARK}.html`；`Hook` 优先 `钩子_{HALLMARK}.php/.html`；不存在则回退默认文件 |
| `CSTART` | `C()` 配置 → `G('CSTART')` | **页面缓存（静态化）开关**（*C*ache *START*）。是否开启全页 HTML 缓存 | `false` | `Bootstrap::loadDbConfig()`（boot 阶段）→ `cacheLoading()`；`View::$caching` 与 `cachePath()` 决定按 `REQUEST_URI` 写静态页还是编译目录缓存 |

**`URL_DEPR` 补充**

- 配置位置：`Source/Inc/Route.inc.php`、`*Route.inc.php`、`route.php`。
- **禁止**设为 `.`，框架会 `halt`（与伪静态后缀冲突）。
- 与 `URL_MODEL`、`URL_HTML_SUFFIX` 配合使用。

**`HALLMARK` 补充**

```php
// 示例：移动端专用模板 index_mobile.html
C('HALLMARK', 'mobile');
```

- `Public/404` 模板不参与千人千面后缀拼接。
- 插件钩子同理：`Hook/demo.php` → 优先 `Hook/demo_mobile.php`。

**`CSTART` 补充**

- 配置位置：`Source/Inc/Config.inc.php` 顶层 `'CSTART' => false`。
- 开启后依赖非文件类缓存驱动（`Cache::notUsedFile()` 为真时 `cacheLoading(true)` 才生效）。
- **关联键**（同为冻结缩写，一并理解）：

| 键名 | 含义 |
|------|------|
| `CTIME` | 页面缓存有效期（秒），默认 `3600` |
| `CTYPE` | 缓存粒度：`0` 全页 / `1` 片段 / `2` 数据 |

### 4.2 已废弃但仍兼容的键

| 旧键 | 正确键 | 说明 |
|------|--------|------|
| `COMPOLE_DIR` | `COMPILE_DIR` | compile 拼写错误 |
| `RAPPNAME` | — | 冻结：关联插件/扩展应用名（Related **App** Name） |

## 6. Security 门面

- 对外 API 使用 camelCase，无 `_` 前缀。
- `_removeXss`、`_setTokenName` 等历史方法保留，新代码使用无下划线别名（见 `Security.class.php` `@deprecated` 标注）。

## 7. 新代码检查清单

1. 属性是否 camelCase 且带类型声明？
2. public 方法是否避免 `_` 前缀？
3. 配置键变更是否双读双写 ≥ 1 个版本？
4. 是否复用现有工具而非新造缩写？
5. Trait 是否单一职责、名称自解释？

## 8. Candy/Class 扩展库

`Candy/Class` 目录遵循与 Core 相同的 camelCase 规则；类文档见 `Doc/Candy/类库文档/Candy/Class/` 与 `Doc/Candy/类库文档/Candy/Extend/`。

| 类 | 文档路径 |
|----|----------|
| `WebSocket` | `Extend/Network/WebSocket.md`、`Class/Network/WebSocket.class.md` |
| `File` | `Class/File.class.md` |
| `DBServer` / `DBService` | `Extend/DB/DBServer.md`、`Class/DB/DBService.class.md` |
| `Attribute` | `Class/Attribute/命名规范.md` |
