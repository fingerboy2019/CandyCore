# 响应式布局语法指南

本指南详细介绍了 Markdown 类库新增的响应式布局语法，支持基于 Bootstrap 栅格系统的响应式布局编写。通过直观的 `>:` 标记语法，您可以轻松创建适配不同屏幕尺寸的页面布局。

## 一、语法概述

响应式布局语法基于最新的div布局语法，采用 `>:` 作为起始标记，后面跟花括号定义样式（如 `>: {.row}` 表示行容器），利用 `>:` 后面的冒号数量来表示列的嵌套层级（如 `>::` 表示2级，`>:::` 表示3级）。所有布局块均以 `>!:` 作为统一的结束标记。这种设计既保持了语法的直观性，又充分利用了 Bootstrap 强大的栅格系统能力。

### 1.1 核心语法规则

| 语法标记 | 作用 | 生成 HTML |
|---------|------|----------|
| `>: {.row}` | 定义行容器 | `<div class="row">` |
| `>: {.row .class}` | 定义带类名的行容器 | `<div class="row class">` |
| `>:: {.class-name}` | 定义列开始 | `<div class="class-name">` |
| `>::: {.class-name}` | 嵌套子列 | 嵌套的 `<div class="class-name">` |
| `>!:` | 结束所有布局块 | - |

### 1.2 语法特点

该语法设计遵循以下核心原则：语法直观易学，用户只需掌握 `>:` 后面的冒号数量即可理解布局层级；层级清晰明确，通过冒号数量精确表达嵌套深度；兼容性好，语法与现有 Markdown 引用语法不冲突，使用 `>:` 固定标记进行区分；灵活强大，支持任意 Bootstrap 类名组合，可实现复杂的响应式设计；嵌套支持完善，允许无限层级嵌套，满足各种复杂布局需求；结束标记统一，使用 `>!:` 即可结束当前所有嵌套布局块。

## 二、基础用法

### 2.1 简单行布局

最基本的用法是创建单行多列布局。以下示例展示了三列卡片布局，在大屏幕上显示三列，中等屏幕上显示两列，移动端占满整行宽度。

```markdown
\>: {.row}
\>:: {.col-12 .col-md-6 .col-lg-4}
### 卡片一
这是第一张卡片的描述内容。在移动设备上会占据整行宽度。
\>:: {.col-12 .col-md-6 .col-lg-4}
### 卡片二
这是第二张卡片的描述内容。支持响应式显示。
\>:: {.col-12 .col-md-6 .col-lg-4}
### 卡片三
这是第三张卡片的描述内容。可以放置任意内容。
\>!:
```

生成的 HTML 结构如下所示，每个卡片都应用了对应的响应式类名。

```html
<div class="row">
    <div class="col-12 col-md-6 col-lg-4">
        <h3>卡片一</h3>
        <p>这是第一张卡片的描述内容。在移动设备上会占据整行宽度。</p>
    </div>
    <div class="col-12 col-md-6 col-lg-4">
        <h3>卡片二</h3>
        <p>这是第二张卡片的描述内容。支持响应式显示。</p>
    </div>
    <div class="col-12 col-md-6 col-lg-4">
        <h3>卡片三</h3>
        <p>这是第三张卡片的描述内容。可以放置任意内容。</p>
    </div>
</div>
```

### 2.2 两列布局

两列布局是最常用的页面布局形式，通常用于主内容加侧边栏的场景。以下示例展示了经典的博客布局结构。

```markdown
\>: {.row}
\>:: {.col-12 .col-md-8}
## 主要内容区
这里是页面的主要内容区域。在中等屏幕及以上设备上占据 8 列宽度，在移动端自动占满整行。
可以放置长篇文章、详细说明或者任何需要重点展示的内容。
\>:: {.col-12 .col-md-4}
## 侧边栏
侧边栏区域通常用于放置导航菜单、广告位、相关文章链接等内容。在中等屏幕及以上设备上占据 4 列宽度。
\>!:
```

### 2.3 等宽列布局

如果不指定具体的列类名，系统将自动创建等宽列布局。这种方式适合创建简单的多列并列效果。

```markdown
\>: {.row}
\>:: {.col}
### 第一列
这是第一列的内容，各列宽度相等。
\>:: {.col}
### 第二列
这是第二列的内容。
\>:: {.col}
### 第三列
这是第三列的内容。
\>!:
```

## 三、嵌套布局

### 3.1 简单嵌套

布局语法支持无限层级的嵌套，可以在一个列内部继续创建新的行和列。以下示例展示了如何在主内容区域内创建嵌套的卡片布局。

```markdown
\>: {.row}
\>:: {.col-md-8}
### 主内容区域
这里是主内容区域，内部可以继续嵌套响应式布局。

\>: {.row}
\>::: {.col-6}
#### 左侧面板
使用三个 `:` 符号定义子列。
这是左侧面板的内容。
\>::: {.col-6}
#### 右侧面板
右侧面板与左侧面板并列显示。
在中等屏幕上各占一半宽度。
\>:: {.col-md-4}
### 侧边栏
外层的侧边栏与主内容区域并列显示。
\>!:
```

生成的嵌套 HTML 结构清晰地展现了层级关系。

```html
<div class="row">
    <div class="col-md-8">
        <h3>主内容区域</h3>
        <p>这里是主内容区域，内部可以继续嵌套响应式布局。</p>
        <div class="row">
            <div class="col-6">
                <h4>左侧面板</h4>
                <p>使用三个 `:` 符号定义子列。</p>
            </div>
            <div class="col-6">
                <h4>右侧面板</h4>
                <p>右侧面板与左侧面板并列显示。</p>
            </div>
        </div>
    </div>
    <div class="col-md-4">
        <h3>侧边栏</h3>
        <p>外层的侧边栏与主内容区域并列显示。</p>
    </div>
</div>
```

## 四、栅格间距控制

### 4.1 基础间距设置

系统支持通过配置控制行内的栅格间距。通过在 `>: {.row}` 后添加间距类名，可以指定不同的间距级别。

```markdown
\>: {.row .g-0}
\>:: {.col-6}
### 无间距列
这一行的列之间没有间距。
\>:: {.col-6}
适合紧密排列的内容。
\>!:
```

### 4.2 间距级别说明

| 参数 | 间距大小 | 适用场景 |
|-----|---------|---------|
| `g-0` | 0px | 紧密排列的图片墙 |
| `g-1` | 4px | 紧凑型卡片列表 |
| `g-2` | 8px | 普通卡片布局 |
| `g-3` | 16px | 标准内容区块 |
| `g-4` | 24px | 宽松布局 |
| `g-5` | 48px | 大间距展示区 |

### 4.3 间距使用示例

```markdown
\>: {.row .g-3}
\>:: {.col-md-4}
### 卡片一
具有标准间距的卡片布局。
\>:: {.col-md-4}
### 卡片二
间距使内容更加清晰易读。
\>:: {.col-md-4}
### 卡片三
避免内容过于紧凑。
\>!:
```

## 五、响应式断点

### 5.1 Bootstrap 断点说明

Bootstrap 5 提供了五个响应式断点，每个断点对应特定的屏幕宽度范围。以下是各断点的详细说明。

| 断点类名 | 设备类型 | 屏幕宽度范围 |
|---------|---------|-------------|
| `col-*` | 超小设备 | < 576px |
| `col-sm-*` | 小设备 | ≥ 576px |
| `col-md-*` | 中等设备 | ≥ 768px |
| `col-lg-*` | 大设备 | ≥ 992px |
| `col-xl-*` | 超大设备 | ≥ 1200px |
| `col-xxl-*` | 超超大设备 | ≥ 1400px |

### 5.2 多断点组合

以下示例展示了如何为同一列指定多个断点，使其在不同屏幕尺寸下呈现不同的宽度比例。

```markdown
\>: {.row}
\>:: {.col-12 .col-sm-6 .col-lg-4 .col-xl-3}
### 响应式卡片一
- 移动端：占满整行
- 小屏及以上：一行两列
- 大屏：一行三列
- 超大屏：一行四列
\>:: {.col-12 .col-sm-6 .col-lg-4 .col-xl-3}
### 响应式卡片二
相同的响应式行为应用于所有卡片。
\>:: {.col-12 .col-sm-6 .col-lg-4 .col-xl-3}
### 响应式卡片三
确保在所有设备上都有良好的显示效果。
\>:: {.col-12 .col-sm-6 .col-lg-4 .col-xl-3}
### 响应式卡片四
灵活的布局适应不同屏幕尺寸。
\>!:
```

### 5.3 隐藏与显示类

除了设置列宽，还可以使用隐藏和显示类来控制内容在不同设备上的可见性。

```markdown
\>: {.row}
\>:: {.col-12}
### 桌面端和移动端都显示
这部分内容在所有设备上都会显示。
\>:: {.d-none .d-md-block .col-12}
### 仅桌面端显示
这部分内容在移动设备上会被隐藏，在中等屏幕及以上设备上显示。
\>:: {.d-md-none .col-12}
### 仅移动端显示
这部分内容仅在移动设备上显示，桌面端会被隐藏。
\>!:
```

## 七、与其他语法结合

### 7.1 结合代码块

响应式布局可以与代码块语法无缝结合，用于展示代码示例及其说明。

```markdown
\>: {.row}
\>::: {.col-lg-6 .col-md-12}
#### 代码示例
这里是代码块的展示区域，代码内容会被正确渲染和着色。

\```php
public function example()
{
    return 'Hello, World!';
}
\```
\>::: {.col-lg-6 .col-md-12}
#### 代码说明
代码块的详细说明部分。可以解释代码的作用、参数和返回值。

- **作用**：返回一个问候语字符串
- **参数**：无
- **返回值**：字符串 `Hello, World!`
\>!:
```

### 7.2 结合表格

布局语法可以与表格语法配合使用，实现更复杂的内容组织。

## 八、注意事项

### 8.1 语法格式要求

在使用响应式布局语法时，请注意以下格式要求以确保正确解析：

第一，行容器标记 `>: {.row}` 后面不能有其他内容，必须单独一行。第二，列标记 `::` 后面需要跟 Bootstrap 类名，类名必须使用 `{.class-name}` 格式包裹，多个类名之间用空格分隔。第三，列内容需要换行并缩进，嵌套层级通过冒号数量表示，如 `:::` 表示3级嵌套。第四，空行不会中断布局解析，可以用于内容分段。第五，所有布局块必须以 `>!:` 结束。

```markdown
# 正确示例
\>: {.row}
\>:: {.col-12 .col-md-6}
这是列内容。
\>!:

# 错误示例（列标记后无类名）
\>::
这是错误的内容。

# 错误示例（>: {.row} 后有多余内容）
\>: {.row} extra-text
\>:: {.col-12}
这是错误的内容。
\>!:
```

### 8.2 与引用语法的区分

响应式布局语法使用 `>: {.row}` 作为固定的行容器标记，与普通的引用语法（以 `>` 开头的内容）不会混淆。这是因为普通引用的 `>` 后面不会紧跟 `row` 关键字。

```markdown
# 普通引用（保持原有功能）
\>> 这是一段引用文字。

# 响应式布局行
\>: {.row}
\>:: {.col-6}
这是布局内容。
\>!:
```

### 8.3 嵌套层级建议

虽然语法支持无限层级嵌套，但建议在实际使用中控制嵌套深度。一般情况下，两到三层嵌套足以满足大多数布局需求，过深的嵌套会增加维护难度。

```markdown
# 推荐：两层嵌套
\>: {.row}
\>:: {.col-8}
\>: {.row}
\>::: {.col-6}
内容
\>::: {.col-6}
内容
\>!:
\>!:

# 不推荐：过多层级嵌套
\>: {.row}
\>:: {.col-8}
\>: {.row}
\>::: {.col-8}
\>: {.row}
\:::: {.col-6}
# 内容层级过深，难以维护
\>!:
\>!:
\>!:
```

### 8.4 性能考虑

对于包含大量响应式布局块的文档，解析性能可能会受到影响。建议在长文档中适度使用布局块，避免过度嵌套。如果页面包含数百个响应式布局，可以考虑将页面拆分为多个子页面。

## 九、常见问题

### 9.1 列内容不显示

如果布局解析后列内容为空，请检查以下几点：列内容是否正确缩进，确保每个内容行都以正确数量的 `>` 开头；列标记 `>::` 后是否有类名，必须指定至少一个 Bootstrap 列类名；是否存在未闭合的语法块，如代码块或引用块。

### 9.2 布局错乱

布局显示异常通常由以下原因导致：混合使用了不同的缩进方式（空格和制表符混用），建议统一使用空格缩进；列的宽度总和超过 12 列，Bootstrap 栅格系统要求一行内所有列宽之和不超过 12；遗漏了行容器标记 `>: {.row}`，每个布局行都必须以 `>: {.row}` 开头。

### 9.3 样式冲突

如果布局样式与页面其他元素产生冲突，可以尝试以下解决方案：为布局添加自定义包装容器，通过 CSS 类名隔离样式影响范围；检查是否有全局样式覆盖了 Bootstrap 的默认样式；在布局块内使用行内样式覆盖特定样式。

## 十、技术实现

### 10.1 解析器工作原理

响应式布局解析器采用状态机模式，逐行扫描 Markdown 文本，识别布局标记并构建对应的 HTML 结构。解析过程分为以下阶段：

第一阶段是标记识别，检测以 `>: {.row}` 开头的行，确定新的布局块开始。第二阶段是列解析，识别列标记 `::`、`:::` 等（通过 `>:` 后面的冒号数量确定嵌套层级），收集列的类名和内容。第三阶段是内容处理，对收集到的列内容应用 Markdown 解析，包括嵌套的布局块。第四阶段是结束标记处理，遇到 `>!:` 时结束当前所有嵌套的布局块。第五阶段是 HTML 生成，将解析结果转换为标准的 Bootstrap 栅格 HTML 结构。

### 10.2 与其他块级元素的交互

响应式布局块的解析时机经过精心设计，确保与其他块级元素正确配合。解析顺序如下：

首先处理图表块（`chartjs` 代码块），其次是代码块（` \`\`\` ` 标记），然后是选项卡块（`:::tab` 语法），接着是自定义容器块（`:::info` 等语法），之后是响应式布局块（`>: {.row}` 语法），然后是列表块（有序和无序列表），接着是表格块，最后是幻灯片块和折叠块。

这种解析顺序确保了布局块内部可以包含其他块级元素，同时外部的布局块不会被内部元素打断。

### 10.3 扩展建议

如果您需要扩展响应式布局的功能，可以考虑以下方向：

第一，自定义列类，添加项目特定的列类名，如 `col-main`、`col-sidebar` 等。第二，间距控制增强，支持更细粒度的水平间距和垂直间距设置。第三，对齐类支持，添加 `justify-content-*` 和 `align-items-*` 类以支持对齐功能。第四，排序类支持，添加 `order-*` 类以支持列的显示顺序控制。
